## 0. 핵심 요약

1. **A5000에서 처음으로 VLM 추론이 돌았다.** 5개 모델을 같은 조건으로 비교 (S-M 실험).
2. **VLM이 4칸을 전부 답하게 하면 VLM 없는 기준선(PT)과 차이가 없다** (완전 정답 0.00–0.17 vs 0.09).
3. **VLM은 "대상 · 움직임"만 맡고, "방향 · 행동"은 규칙으로 정하면** Qwen2.5-VL-7B 완전 정답 0.09 → **0.39**. (사후 분석 → VIABench로 재확인 필요)
4. **잠정 선택: Qwen2.5-VL-7B (정확도) / Qwen2.5-VL-3B (속도 2배, 온디바이스 후보).** 논문 1위 InternVL3.5-8B는 우리 조건에서 최하위.
5. **5개 모델 모두 "신호등이 초록으로 바뀜"을 못 맞힘** → 시간 변화 인식이 공통 약점.

## 1. 실험 설정 (S-M)

| 항목 | 내용 |
|---|---|
| 목적 | 트리거가 경고할 때 **어느 VLM이 대상을 가장 정확 · 빠르게 설명하나** |
| 호출 시각 | **정답 시각** (라벨의 경고 시작 t_start) — 트리거 오류를 빼고 VLM만 비교 |
| 데이터 | 종설 10편의 경고 정답 23개 (`labels/v3`) — 정지 장애물 S2 13 · 신호등 S3 5 · 계단 S4 5 · **움직이는 물체 S1 0** |
| 입력 | 트리거 시각까지 **과거 8장 · 1초 간격** (VIABench Table 5), 긴 변 448 px, 대상은 **빨간 박스** |
| 출력 | JSON 스키마 강제: 대상 · 방향 · 움직임 · 행동 · 위험 여부 → 템플릿으로 한국어 문장 |
| 생성 | temperature 0, 최대 64 토큰, 같은 입력 3회 (지연 중앙값) |
| 서버 | vLLM 0.31.0, bf16, RTX A5000 24 GB |
| 기준선 PT | VLM 없이 트리거 정보(YOLO 클래스 · bbox 위치 · 규칙표)만으로 같은 JSON |

## 2. 채점 기준

| 지표 | 계산 | 근거 |
|---|---|---|
| 칸별 정확도 | 대상(`target_ok`에 포함) · 방향(좌/정면/우) · 움직임 · 행동(규칙표 허용 집합) | docs/09 |
| **완전 정답** | 4칸 모두 맞은 비율 — 사용자가 틀린 정보를 하나도 안 듣는 경우 | docs/09 |
| 혼동 / 환각 | 화면 속 다른 물체를 말함 / 검출된 적 없는 물체를 말함 | CHAIR 방식 근사 |
| ESTP S̄ | (내용 1–5 + 시점 0–5) / 10, 정답 구간 끝 + 2 s 넘으면 0 | ESTP-Bench (NeurIPS'25) |
| 지연 · 입력 토큰 | 호출 전체 시간 중앙값 · prompt 토큰 | VIABench · StreamingTOM |
| 신뢰구간 · 검정 | 영상 단위 부트스트랩 95 % · McNemar / Wilcoxon (Holm) | docs/09 |

## 3. 결과

### 3-1. VLM이 4칸 전부 출력 (`results/vlm/_eval/sm_F8.md`)

| 모델 | 완전 정답 | 대상 | 방향 | 움직임 | 행동 | 환각 | 지연 | ESTP S̄ |
|---|---|---|---|---|---|---|---|---|
| Qwen2.5-VL-7B | 0.09 | **0.87** | 0.65 | **0.61** | 0.22 | **0.04** | 0.94 s | 0.749 |
| Qwen2.5-VL-3B | 0.00 | 0.61 | 0.52 | 0.48 | 0.39 | 0.13 | **0.52 s** | 0.752 |
| Qwen3-VL-8B | 0.09 | 0.83 | 0.57 | 0.48 | 0.43 | 0.13 | 1.02 s | 0.735 |
| InternVL3.5-8B | 0.09 | 0.70 | 0.43 | 0.52 | 0.43 | 0.13 | 1.05 s | 0.711 |
| InternVL3.5-4B | 0.17 | 0.74 | 0.43 | 0.39 | 0.26 | 0.17 | 0.64 s | 0.724 |
| PT (VLM 없음) | 0.09 | 0.52 | 0.91 | 0.09 | 0.83 | 0 | 0 s | 0.835 |

- 형식 오류 0 (전 모델). 완전 정답 차이는 유의하지 않음 (McNemar p = 1.0), 지연 차이는 유의 (p < 0.001).
- ESTP S̄는 정답 구간이 짧아(중앙값 2 s) **지연에 좌우됨** → 정답 시각 비교에서는 완전 정답 · 칸별로 판단.

### 3-3. 오류 패턴

| 패턴 | 예 |
|---|---|
| 행동은 모델마다 습관 | 7B "기다리세요", Qwen3 · InternVL8B 거의 전부 "조심하세요" → **행동은 규칙으로** |
| 좌우 판단 약함 | 정면 박스를 "왼쪽" → **방향은 bbox로** |
| 시간 변화 못 봄 | 초록으로 바뀐 신호등 4개를 5개 모델 모두 "빨간불" 또는 "정지" |
| 계단 위/아래 | 대부분 "정지" 또는 반대 방향 |
| 박스 지정 실패 | InternVL8B: 가판대 → 차량, 표지판 → 사람 |

## 4. 해석 · 한계

| 항목 | 내용 |
|---|---|
| 역할 분담 | VLM의 이득은 **대상(0.52 → 0.87)과 움직임(0.09 → 0.61)**. 방향 · 행동은 규칙이 낫다 → 트래커 · 트리거가 판단, VLM은 "무엇이 · 어떻게"만 |
| 논문 순위와 다름 | VIABench Table 4 (자유 문장 + GPT 판정)에선 InternVL3.5-8B 1위. 우리 조건 (박스 지정 · 칸 선택)에선 7B 1위 |
| 표본 | 23개 · S1 0개 · 라벨은 Claude 초안 → 순위는 잠정 |
| 사후 분석 | 하이브리드는 결과를 보고 설계 → **VIABench에서 재확인해야 주장 가능** |
| 입력량 | InternVL은 정사각형 448 타일이라 토큰 1.6배 (2,468 vs 1,564)인데도 낮음 |

## 5. 평가 계획 — 4단계

YOLO 트래커 + 트리거가 **판단**(언제 · 무엇이 위험), VLM + TTS는 **전달**(정확 · 빠르게).

| 단계 | 질문 | 방법 | 지표 | 상태 |
|---|---|---|---|---|
| **1. VLM 선택** | 어느 VLM이 대상을 가장 정확 · 빠르게 설명하나 | 정답 시각 호출 | 완전 정답 · 칸별 · 환각 · 지연 | 잠정 7B / 3B → **VIABench 정답 시각으로 확정** |
| **2. 스트리밍 긴급 경고** | 위급 상황에서 **경고가 VLM을 기다리지 않고 바로 나오나** | 녹화 영상을 실제 속도로 재생: YOLO → 트리거 → 즉시 경고(미리 합성 wav) + VLM 설명 | 경고 지연(정답 시작 → 첫 소리) · 마감 안 비율 · 설명 지연 · ESTP-F1 · VLM 호출 수 | 미착수 |
| **3. TTS 선택** | 어느 한국어 TTS가 빠르고 알아듣기 쉬운가 | 같은 문장 세트를 후보별 합성 | 첫 소리 시간 · 실시간 배율 · ASR 역인식 오류율(CER) · 자동 MOS | 미착수 (GPU 거의 불필요 → 먼저 가능) |
| **4. 출력 정합성** | VLM이 말하려던 내용이 소리로 정확히 전달되나 | JSON → 문장 → TTS → ASR → 4칸 복원 | 문장 CER · 칸 복원율 | 미착수 |

### 공개 벤치마크 평가 방식과 대응

| 방식 | 예 | 우리 단계 |
|---|---|---|
| ① 질문 시점에 1회 호출 (객관식 정확도) | OVO-Bench · Video-MME | 1단계 (= 정답 시각 호출) |
| ② 스트리밍 + 시점 · 내용 결합 채점 | ESTP-F1 · VIABench PDR · PAUC | 2단계 (트리거가 호출 시점 결정) |
| ③ 효율 | TTFT · 실시간 배율 · 메모리 | 모든 단계에서 같이 측정 |

### 비용 추정 (A5000)

근거: 7B · F8 호출 1.0–1.3 s (실측), B0 트리거 분당 3.5회 (종설 10편), 동시 요청 3배 가정 (미측정).

| 실험 | 데이터 | GPU 시간 |
|---|---|---|
| 1단계: VIABench 정답 시각, 7B + 3B, 장애물 관련 정답 8,051개 | 66 GB | 약 2–5 h |
| 2단계: YOLO + 트리거, VIABench 영상 49.8 h | 〃 | 3–6 h (1회) + VLM 2–7 h |
| (선택) OVO-Bench 실시간 837문항 | 46 GB | 모델당 0.5–1 h |

- VIABench 사전 경고: 영상 530편 · 정답 13,152개 (장애물 경고 6,776) · 주석은 `benchmarks/`에 받아 둠.

## 6. 서버 재설치 순서 (다음 대여 때 약 10분)

1. 저장소(`vlmcall`)가 빈 볼륨으로 올 수 있음 → `종합설계/` + `6주차/종설 데이터/` + `6주차/best_E0.pt`를 tar로 올림
2. `sed -i 's/\r$//'`로 .sh · .py 줄바꿈 변환 (윈도우 CRLF면 bash 실패)
3. `sudo apt-get install -y tmux`
4. `FAST=/home/ubuntu/fast bash code/p0/setup_server.sh /home/ubuntu/runyourai/vlmcall` (약 5분)
5. `bash code/p0/run_sm.sh "<모델들>" F8 3` — 서버 로그는 `logs/`

| 문제 | 해결 (코드에 반영됨) |
|---|---|
| flashinfer JIT: nvcc 없음 / 버전 불일치 | `serve_vllm.py`가 `VLLM_USE_FLASHINFER_SAMPLER=0` 설정 (어텐션은 원래 FLASH_ATTN) |
| InternVL `max_dynamic_patch` 오류 | `config.py`에서 `--hf-overrides`로 전달 |
| ssh 안에서 `pkill -f "vllm serve"` | 자기 셸까지 죽음 → tmux 세션 안에서만 사용 |
