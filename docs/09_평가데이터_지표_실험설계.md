# VLM 단계 정량 평가 — 평가 데이터 · 라벨 · 지표 · 실험 절차

작성 2026-10-06 · 담당 박상준 · 관련: [`08_스트리밍_VLM_호출_효율화.md`](08_스트리밍_VLM_호출_효율화.md) (비교군 P0–P5), [`04_평가데이터_라벨.md`](04_평가데이터_라벨.md) (종설 10편 라벨)

> 목표: **사람이 점수를 매기지 않고**, 라벨과 출력만으로 스크립트가 숫자를 낸다. 사람은 라벨을 만들 때만 들어간다.

## 0. 한 장 요약

1. **문장을 채점하지 말고 칸을 채점한다.** 경고 하나를 `대상 · 방향 · 움직임 · 행동` 네 칸으로 라벨링하고, VLM도 같은 네 칸(JSON)으로 답하게 한다. 그러면 칸마다 **정답/오답이 기계적으로** 정해진다.
2. **대표 지표는 ESTP-F1(칸)이다.** ESTP-F1 (NeurIPS'25) 식과 시점 허용 폭(앞 1 s · 뒤 2 s)을 원문 그대로 쓰고, 내용 점수만 LLM 판정 대신 4칸 채점으로 바꿨다 (정의는 [`10`](10_공개벤치마크_평가지표.md) §3). 적시 정답률(TCR)은 원인 분석과 발표 그림용 보조 지표로 쓴다.
3. **VLM이 필요한 이유도 숫자로 보인다.** VLM 없이 트리거 정보만으로 만든 템플릿 문장(비교군 **PT**)을 같은 지표로 채점해서 VLM의 이득을 뺀다.
4. **VLM을 트리거 검증기로 쓸 때의 효과**(오탐 거르기)도 같은 라벨로 잰다.
5. LLM 판정은 주 지표에서 뺀다. 근거: VIABench는 문장 정확도(MPS)를 GPT-5 판정으로 쟀지만, VIABLE (EMNLP'26)은 가장 좋은 판정 모델(GPT-5.4)도 단일 오류 진단 정확도가 **52.6 %**, **자기 선호 편향이 94.2 %**라고 보고했다.

## 1. 근거 — 기존 벤치마크는 어떻게 쟀나

| 벤치마크 | 시점 지표 | 내용 지표 | 우리가 가져오는 것 / 바꾸는 것 |
|---|---|---|---|
| **VIABench** (arXiv'26, 시각장애인 촬영 761편) | **PDR**: 정답 구간 [ts, te] 안에 맞는 과제의 안내를 하면 탐지 | **MPS**: GPT-5가 정답 문장과 비교해 0–1 점수. **위치 · 종류 · 행동 지시**가 틀리면 감점 | PDR은 그대로. MPS가 보는 **위치 · 종류 · 행동을 라벨 칸으로 꺼내** 판정 모델 없이 채점 |
| WalkVLM (ICCV'25) | TRF (시간 중복 F1) | ROUGE · TF-IDF · GPT 점수 | 문장 겹침 지표는 짧은 한국어 경고에 약함 → 보조로만 |
| EgoBlind | — | GPT-4o-mini 정/오 판정 (사람과 κ 0.88) | 판정 모델 대신 칸 정답 일치 |
| VIABLE (EMNLP'26) | — | VLM 판정 모델 신뢰도 자체를 평가 | **판정 모델을 주 지표로 쓰지 않는 근거** |

VIABench 보고: Qwen2.5-VL-7B는 응답 하나에 **약 4.6초**가 걸린다. 우리 P0의 출발점 참고값이다.

## 2. 평가 데이터

| 세트 | 내용 | 규모 (예상) | 쓰임 |
|---|---|---|---|
| **D1 팀 촬영** | 3명 × (2분 × 8–10 + 5분 × 2), 10/7–8 촬영 | 약 80–90분 | **주 평가** |
| **D2 종설 10편** | VIABench 원본 10편, 04 문서의 재매핑 라벨 (S1+S2 13 · S3 5 · S4 5) | 9.1분, 경고 23개 | 개발용 (이미 여러 번 봤음) |
| D3 VIABench 추가 | 나머지 영상에서 시나리오별로 뽑은 50편. 영어 정답 문장에서 네 칸을 규칙으로 추출 후 10 % 확인 | 경고 수백 개 (확인 필요) | 표본 수 늘리기 (선택) |

### 2-1. 개발 / 시험 분리 (프롬프트 튜닝 누수 방지)

- **개발 세트:** D2 전부 + D1에서 **사람마다 2분 영상 2개** (시나리오가 고르게 섞이도록 고름).
- **시험 세트:** D1 나머지 + D3.
- 프롬프트, 프레임 수, 문턱은 **개발 세트에서만** 정한다. 시험 세트는 비교군마다 **한 번만** 돌린다.

### 2-2. 필요한 표본 수

- 이진 지표(정답률 70 % 근처)의 95 % 신뢰구간 반폭은 경고 30개일 때 약 ±16 %p, 100개일 때 ±9 %p, 200개일 때 ±6 %p다.
- 그래서 **시험 세트에 S1+S2 경고 100개 이상**을 목표로 한다. 모자라면 D3로 채운다.
- 비교군 간 비교는 **같은 경고에 대한 짝 비교**(McNemar)라서 단순 신뢰구간보다 작은 차이도 잡힌다.

## 3. 라벨 설계

### 3-1. 팀원이 적는 것 (촬영 직후, 기존 형식에 두 칸 추가)

```
영상 / 시작~끝 / 대상 / 움직임 / 설명
영상 1 / 00:35~00:40 / 자전거 / 접근 / 오른쪽 앞에서 자전거가 다가옴
영상 1 / 02:10~02:15 / 나무 / 정지 / 정면 보행로 위 가로수
영상 2 / 00:50~00:58 / 신호등 / 빨강→초록 / 횡단보도 신호 바뀜
```

- **대상**은 아래 세부 어휘 중에서 고른다. **움직임**은 아래 목록 중 하나.
- **방향과 행동은 적지 않는다.** 방향은 대상 bbox에서 계산하고, 행동은 규칙표(§3-3)에서 나온다. 사람마다 다르게 적을 여지를 없앤다.
- 경고하면 안 되는 장면(멀어지는 자전거, 경로 밖 자전거)은 기존 합의대로 라벨 없이 영상에만 담는다.

### 3-2. 라벨 칸 (최종 JSON, 04 문서 형식 확장)

```json
{"clip": "d1_sj_03", "events": [
  {"id": 4, "kind": "warn", "scenario": "S1",
   "t_start": 35.0, "t_end": 40.0,
   "target_coarse": "bicycle", "target_fine": "bicycle",
   "motion": "approaching",
   "target_track": {"frame": 1050, "bbox": [1210, 380, 1490, 860]},
   "direction": "right",
   "action_ok": ["stop", "veer_left"],
   "text_ref": "오른쪽 앞에서 자전거가 다가옴",
   "annotator": "sj", "double_check": null}]}
```

| 칸 | 값 | 누가 / 어떻게 |
|---|---|---|
| `t_start, t_end` | 초 | 팀원 |
| `scenario` | S1 이동체 · S2 정적 장애물 · S3 신호 · S4 단차 | 대상에서 자동 |
| `target_coarse` | 검출기 10클래스: person, bicycle, scooter, motorcycle, car, bus, other_vehicle, obstacle, stairs, traffic_light | 대상에서 자동 |
| `target_fine` | coarse가 obstacle일 때 세분: tree, pole, bollard, sign, stall, parked_bicycle, parked_scooter, bench, barrier, other | 팀원 (대상 칸) |
| `motion` | S1·S2: approaching · static · receding · crossing / S3: red · green · to_green · to_red / S4: up · down | 팀원 (움직임 칸) |
| `target_track` | 대상의 bbox (`t_start` 프레임) | **반자동**: 검출·추적 결과에서 클래스가 맞고 가장 경로 중앙에 가까운 트랙을 골라 확인 시트(그림)로 만든 뒤 사람이 O/X. 틀리면 트랙 번호만 고침 |
| `direction` | left · front · right | **자동**: bbox 중심 x가 화면 폭의 1/3 미만 left, 2/3 초과 right, 나머지 front (회전 영상은 보정 후) |
| `action_ok` | 허용 행동 집합 (§3-3) | **자동**: 규칙표 |
| `text_ref` | 한국어 참고 문장 | 팀원 (설명 칸), 보조 지표에만 사용 |

### 3-3. 행동 규칙표 (`action_ok`)

행동 어휘: `stop` 멈춤 · `veer_left` 왼쪽으로 · `veer_right` 오른쪽으로 · `wait` 기다림 · `cross` 건넘 · `caution` 주의하며 진행

| 시나리오 | 조건 | 허용 행동 |
|---|---|---|
| S1 이동체 | 접근 · 정면 | stop, veer_left, veer_right |
| | 접근 · 왼쪽 | stop, veer_right |
| | 접근 · 오른쪽 | stop, veer_left |
| | 가로지름 | stop, wait |
| S2 장애물 | 정면 | veer_left, veer_right, stop |
| | 왼쪽 (경로 안) | veer_right, caution |
| | 오른쪽 (경로 안) | veer_left, caution |
| S3 신호 | red · to_red | wait |
| | green · to_green | cross |
| S4 단차 | up · down | stop, caution |

규칙표는 **라벨링 전에 고정**하고, 바꾸면 모든 비교군을 다시 채점한다.

### 3-4. 라벨 품질 (정량)

- 경고의 **20 %를 다른 팀원이 한 번 더** 라벨링한다.
- 보고: 구간 **tIoU 평균**, `target_fine` · `motion`의 **Cohen κ**, `target_track` 일치율.
- κ < 0.6인 칸은 정의를 고친 뒤 다시 라벨링한다.

## 4. VLM 출력 형식 (모든 비교군 공통)

```json
{"hazard": true, "target": "bicycle", "direction": "right", "motion": "approaching", "action": "veer_left"}
```

- 프롬프트에 위 어휘 목록을 그대로 넣고 **그 안에서 고르게** 한다. 어휘 밖 답은 동의어 사전(`bike → bicycle`, `kickboard → scooter` …)으로 정규화하고, 그래도 안 맞으면 오답.
- JSON이 깨지면 **형식 오류**로 따로 세고 오답 처리한다 (형식 오류율도 지표).
- 한국어 문장은 이 JSON을 템플릿에 넣어 만든다 → TTS.

## 5. 지표 (모두 자동 계산)

### 5-1. 내용 정확도 — 정답 시각에 호출했을 때 (트리거 오차 제외)

| 지표 | 정의 | 비고 |
|---|---|---|
| **대상 정확도 (coarse)** | `pred.target`을 coarse로 올린 값 = `target_coarse` | 10클래스 |
| **대상 정확도 (fine)** | `pred.target` = `target_fine` (obstacle 경고만) | **VLM이 검출기보다 나은 지점** |
| **방향 정확도** | `pred.direction` = `direction` | 3분류 |
| **움직임 정확도** | `pred.motion` = `motion` | 접근/정지/멀어짐/가로지름, 신호 상태 |
| **행동 적합률** | `pred.action` ∈ `action_ok` | |
| **완전 정답률 (FCR)** | 위 네 칸(대상 coarse · 방향 · 움직임 · 행동)이 모두 맞음 | 주 내용 지표 |
| **대상 혼동률** | 틀린 대상이 같은 시각 화면 안 **다른 트랙**의 클래스와 같음 | 다른 물체를 설명함 |
| **대상 환각률** | 틀린 대상이 그 프레임 창의 어떤 트랙·라벨에도 없음 | CHAIR(Rohrbach 외, EMNLP'18)의 객체 환각 정의를 경고 단위로 적용 |
| 형식 오류율 | JSON 파싱 실패 · 어휘 밖 답 | |
| 클래스별 macro-F1 | `target_coarse`별 F1 평균 | 자전거·킥보드처럼 적은 클래스가 묻히지 않게 |

### 5-2. 지연 · 비용

| 지표 | 정의 |
|---|---|
| 경고 지연 | 트리거 → 경고 템플릿 첫 소리 |
| **설명 지연** | 트리거 → 설명 첫 소리 = 입력 준비 + TTFT + 디코딩 + TTS 첫 소리 (단계별로 따로 기록) |
| 시각 토큰 수 · 출력 토큰 수 | 호출당 |
| 최대 GPU 메모리 | 호출 중 최대값 |
| **영상 1분당 GPU 시간** | 1분 영상을 처리하는 동안 GPU가 실제로 일한 초. P3 · P5는 트리거가 없어도 계속 일함 → 교수님 "연산량" 질문에 답하는 숫자 |

### 5-3. 보조 지표 — 적시 정답률 (TCR) (주 지표 ESTP-F1(칸)은 10 문서 §3)

```
TCR(budget) = (완전 정답이면서 설명 첫 소리 시각 ≤ t_start + budget 인 경고 수) / (전체 경고 수)
```

- **기본 budget = 해당 경고의 `t_end − t_start`** (정답 구간이 끝나기 전에 말해야 함, VIABench PDR과 같은 기준).
- budget을 0.5–6초로 바꿔 가며 **TCR 곡선**을 그린다. 곡선 아래 면적이 클수록 "빠르고 정확한" 비교군.
- 정확하지만 느린 비교군(예: 7B 원본)과 빠르지만 덜 정확한 비교군(예: 가지치기)이 **같은 축**에서 비교된다.

### 5-4. VLM을 트리거 검증기로 쓸 때 — 실제 트리거 시각

규칙 트리거의 이벤트마다 라벨과 대조해 **참(TP)** / **오탐(FP)**을 정한다. TP는 경고 구간 [ts − 4 s, te] 안, FP는 어떤 경고 · 중립 구간에도 걸리지 않는 경우다.

| 지표 | 정의 |
|---|---|
| **오탐 거름률** | FP 이벤트 중 VLM이 `hazard: false`라고 한 비율 |
| **참 유지율** | TP 이벤트 중 VLM이 `hazard: true`라고 한 비율 |
| 시스템 오탐/분 · PDR | VLM 검증 전과 후 |

두 가지 운용 방식을 함께 잰다.
- **빠른 모드:** 경고는 바로 하고, VLM은 설명만 한다 (오탐 그대로, 경고 지연 최소).
- **검증 모드:** VLM이 `hazard: true`라고 할 때만 경고한다 (오탐 감소, 경고 지연 = 설명 지연).

→ "트리거를 과하게 고도화하지 않고 VLM으로 거르면 얼마나 되나"를 숫자로 보여 준다.

### 5-5. 시스템 전체 (P5 end-to-end 비교용)

- **PDR**, **PDR (4초 앞 허용)**, **오탐/분**, **리드타임** (`t_end − 경고 시각`) — 05 문서 정의 그대로.
- **내용 포함 PDR:** 정답 구간 안에서 경고했고 그 설명이 완전 정답인 비율.

### 5-6. 보조 지표 (주 결론에 쓰지 않음)

- **chrF++** (한국어 글자 n-gram): 조립된 문장 vs `text_ref`. 짧은 한국어 문장에서 단어 단위 지표(BLEU · ROUGE)보다 안정적.
- **MPS(오픈)**: VIABench MPS의 GPT 판정 대신 오픈소스 판정 모델(Prometheus 2)과 BGE-M3 유사도로 계산. 비공식이며 판정 모델 일치도 검사(10 문서 §5-4)를 통과할 때만 보고.

### 5-7. 통계

- **짝 비교:** 같은 경고에 대한 두 비교군의 정/오 → **McNemar 검정**. 지연 → **Wilcoxon 부호 순위 검정**.
- **신뢰구간:** 영상 단위 부트스트랩 1,000회, 95 %.
- **다중 비교:** P1–P5를 모두 P0와 비교하므로 **Holm 보정**.
- 지연은 3회 반복의 중앙값, 첫 호출(워밍업)은 버린다.

## 6. 비교군과 실험 절차

### 6-1. 비교군 (08 문서 + VLM 없는 기준선)

| 비교군 | 설명 |
|---|---|
| **PT** | **VLM 없음.** 트리거의 클래스 + bbox 방향 + 규칙표 첫 행동 + `motion = approaching` 고정 → 같은 JSON. 지연 ≈ 0 |
| P0 | 트리거 때 VLM 호출. 모델은 S-M, 프레임 수는 S-F로 결정 ([`11`](11_P0_설계근거.md)) |
| P1 | P0 + FastVID |
| P2 | TimeChat-Online-7B |
| P3 | StreamingVLM (상시 KV, 트리거 때 질문만) |

| P5 | MMDuet2 (트리거 없음, end-to-end) — §5-5로만 비교 |

### 6-2. 실험 단계

| 단계 | 질문 | 조건 | 주 지표 | 채택 규칙 (미리 정함) | 시점 |
|---|---|---|---|---|---|
| **S0** | 끝까지 돌아가나 | P0, 개발 세트 | 형식 오류율, 설명 지연 | 형식 오류 < 5 % | 10/8 |
| **S1** | bbox를 어떻게 넣나 | P0 안에서: 없음 / 박스 그림 / 좌표 텍스트 / 둘 다 / 크롭 + 저해상도 전체 (개발 세트) | FCR, 대상 혼동률 | FCR 최고. 차이가 McNemar 유의하지 않으면 토큰이 적은 쪽 | 10/9 |
| **S2** | VLM이 템플릿보다 나은가 | PT vs P0 (3B · 7B), 시험 세트 | **ESTP-F1(칸), FCR, fine 대상 정확도, 움직임 정확도** | — (결과 보고) | 10/10 |
| **S3** | 토큰을 줄여도 되나 | P0 vs P1 | TCR, FCR, 시각 토큰 | P1의 FCR 하락이 유의하지 않고 TCR이 높으면 채택 | 10/10 |
| **S4** | 스트리밍 모델이 나은가 | P0 vs P2 vs P3 | TCR, 영상 1분당 GPU 시간 | TCR 우위 + GPU 시간 2배 이내 | 10/11 |
| **S5** | 영역 전용 모델이 나은가 | P0 vs P4 (7B · 2B) | FCR, 대상 혼동률 | 혼동률 유의 감소 | 10/11 |
| **S6** | VLM으로 오탐을 거를 수 있나 | 최선 비교군 × (빠른 모드 · 검증 모드), 실제 트리거 시각 | 오탐 거름률, 참 유지율, 오탐/분, 경고 지연 | 참 유지율 ≥ 90 %에서 오탐/분 감소폭 | 다음 주 |
| **S7** | 분리형이 end-to-end보다 나은가 | (트리거 + 최선) vs P5 | 내용 포함 PDR, 오탐/분, 영상 1분당 GPU 시간 | 결과 보고 | 다음 주 |
| **S-T** | TTS | 미리 합성 wav · Supertonic-3 · CosyVoice | 첫 소리 지연, RTF, **CER** (합성 음성 → Whisper 받아쓰기 → 원문 대비 글자 오류율) | CER < 5 %에서 첫 소리 지연 최소 | 10/10 |
