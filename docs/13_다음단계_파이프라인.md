# 다음 단계 파이프라인 — 실행 시스템 · 4단계 실험 · 일정

작성 2026-10-07 · 담당 박상준 · 관련: [`12`](12_VLM비교실험_결과_평가계획.md) (VLM 비교 결과), [`14`](14_VLM평가데이터_최소라벨링.md) (평가 데이터)

역할 분담: **YOLO 트래커 + 트리거 = 판단** (언제 · 무엇이 위험), **VLM + TTS = 전달** (정확 · 빠르게).

---

## A. 실행 시스템 (녹화 영상 시연 기준)

```
카메라 프레임 (녹화 영상을 실제 속도로 재생)
   │
   ▼
① YOLO-seg (E0) + ByteTrack ─────────── 트랙: id · 클래스 · bbox · 마스크
   │
   ▼
② 트리거 (임태규 규칙, 교체 가능 인터페이스) ── 이벤트: 시각 · 트랙 id · 클래스 · 시나리오
   │
   ▼
③ 분배기 ──┬─▶ ④ 즉시 경고 "왼쪽 오토바이" (미리 합성한 wav) ─────▶ 우선순위 높음
          │
          └─▶ ⑤ VLM 설명 (비동기 — 경고를 막지 않음)
                 과거 8프레임 + 빨간 박스 → Qwen2.5-VL → {대상, 움직임, 위험 여부}
                 방향 = bbox 위치, 행동 = 규칙표
                 → 한국어 문장 → ⑥ TTS 합성 ─────────────────────▶ 우선순위 보통
                                                                    │
                                                         ⑦ 오디오 재생 큐
                                                 (경고가 설명을 끊고 먼저 재생,
                                                  늦은 설명은 버림)
   ⑧ 모든 단계의 시각을 로그로 → 채점
```

| 단계 | 하는 일 | 상태 | 할 일 |
|---|---|---|---|
| ① 인식 · 추적 | YOLO E0 + ByteTrack | 있음 (`dump_tracks.py`) | 실시간 스트림용 프레임 단위 함수화 |
| ② 트리거 | 언제 경고할지 | B0만 있음 | 인터페이스 `step(트랙들, t) → 이벤트들`. 임태규 최종 코드를 그대로 끼움 |
| ③ 분배기 | 이벤트 → 경고 + 설명 | 없음 | 같은 트랙 중복 방지(쿨다운), VLM 작업 큐 |
| ④ 즉시 경고 | VLM을 기다리지 않고 바로 소리 | 템플릿만 (`warn_text`) | 클래스 × 방향 wav 미리 합성 |
| ⑤ VLM | 무엇이 · 어떻게 움직이나 | 동작 확인 | **하이브리드 정식 구현** — 출력 3칸(대상 · 움직임 · 위험 여부) |
| ⑥ TTS | 문장 → 소리 | 뼈대만 (`tts.py`) | 모델 선정 (3단계) |
| ⑦ 재생 큐 | 경고 우선, 늦은 설명 폐기 | 없음 | 우선순위 큐 + 마감 시각 |
| ⑧ 로그 | 단계별 시각 | 일부 | 공통 로그 형식 |

**정해야 할 규칙 (VLM ↔ 트리거 정합성):**
- VLM이 "위험 아님" → 경고는 이미 나갔으므로 설명을 생략할지
- VLM 대상 ≠ YOLO 클래스 (예: 오토바이 vs 킥보드) → 어느 쪽을 말할지

## B. 4단계 실험

### 0단계 (준비) — 하이브리드 정식 구현 · 데이터 보강

| 할 일 | 내용 | 산출물 |
|---|---|---|
| 하이브리드 구현 | JSON 스키마 3칸, 방향 · 행동은 코드가 채움 | `run_p0.py --mode hybrid` |
| 23개 재실행 | 사후 채점이 아니라 실제로 3칸만 답할 때도 0.39가 나오나 | 7B · 3B 결과 |
| 팀 영상 라벨 변환 | 10/7–8 촬영분 → v3 형식, **움직이는 물체(S1) 정답 확보** | `labels/v3/` 추가 |
| VIABench 칸 자동 추출 | 정답 문장 → 대상 · 움직임 · 방향 (docs/14) | 평가용 정답 |

### 1단계 — VLM 선택 (정답 시각 방식)

| 항목 | 내용 |
|---|---|
| 질문 | 7B와 3B 중 무엇을 쓰나 |
| 데이터 | 종설 23개 + 팀 영상 + VIABench 장애물 관련 약 8,000개 + GuideDog Object (docs/14) |
| 방법 | 정답 시작 시각에 VLM 호출, 하이브리드 채점 |
| 지표 | 완전 정답 · 대상 · 움직임 정확도 · 환각 · 지연 |
| 결정 기준 | 7B가 3B보다 **유의하게** 높으면 (McNemar p < 0.05) 7B, 아니면 3B (2배 빠름, 8–11주차 온디바이스) |
| 추가 확인 | 신호등 바뀜 장면만 F32 · 신호등 크롭으로 재시험 |
| GPU | 약 2–5 h, VIABench 66 GB |

### 2단계 — 스트리밍에서 위급할 때 바로 말하나

| 항목 | 내용 |
|---|---|
| 질문 | 실시간 재생에서 **위험 → 소리**가 제때 나오나, VLM이 바빠도 경고가 밀리지 않나 |
| 방법 | A 시스템 전체를 녹화 영상에 실제 속도로. YOLO · VLM · TTS를 A5000 한 대에 |
| 지표 | **경고 지연** (정답 시작 → 경고 첫 소리) · **마감 안 비율** (정답 구간 끝 + 2 s 전) · 설명 지연 · 버린 설명 수 · ESTP-F1 (트리거 오탐 포함) · 분당 VLM 호출 수 · 최대 GPU 메모리 |
| 비교 | ① PT (VLM 없음) ② 우리 (트리거 때만 VLM) ③ **2초마다 VLM 계속 호출** → "호출 X % 감소에 성능 유지" (docs/08 핵심 근거) |
| 부하 시험 | 위험이 연달아 생기는 구간에서 경고 지연 |
| 주의 | 7B (bf16 약 16 GB) + YOLO + TTS → vLLM 메모리 비율 0.9 → 약 0.7 |
| GPU | 종설 · 팀 영상 1 h 이내 / VIABench 3–6 h + VLM 2–7 h |

### 3단계 — TTS 선택 (서버 없이 먼저 가능)

| 항목 | 내용 |
|---|---|
| 질문 | 어느 한국어 TTS가 빠르고 정확하게 들리나 |
| 후보 | Supertonic (docs/08) + 로컬 한국어 지원 공개 모델 — **조사 후 확정** |
| 문장 세트 | 즉시 경고 약 30개 (클래스 × 방향) + VLM 문장 조합에서 층화 추출 |
| 지표 | **첫 소리 시간** · 실시간 배율 · **ASR 역인식 오류율** (Whisper 등) · 자동 MOS (한국어 적합성 확인 필요) · 메모리 |
| 환경 | A5000 + 노트북 CPU (온디바이스 대비) |
| 결정 기준 | 오류율 기준 이하 중 첫 소리가 가장 빠른 것 |

### 4단계 — 출력 정합성 (말하려던 내용이 소리로 전달되나)

| 항목 | 내용 |
|---|---|
| 방법 | VLM JSON → 문장 → TTS → ASR → **4칸 되돌리기** |
| 지표 | 문장 오류율 · **칸 복원율** |
| 고칠 것 | 복원율 낮은 단어 교체 (예: 볼라드 → 말뚝), 조사, 숫자 읽기 |
| 데이터 | 1 · 2단계 출력 재사용, GPU 거의 불필요 |
