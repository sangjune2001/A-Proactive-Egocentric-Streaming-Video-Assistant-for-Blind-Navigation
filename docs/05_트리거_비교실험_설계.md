## 0. 결론 먼저 — 따로 하나, end-to-end로 하나

**둘 다 한다. 순서는 ① 트리거만 → ② 호출 방식만 → ③ 전체 시스템.**

탑티어 연구는 "언제 말할지"와 "무엇을 말할지"를 두 갈래로 다룬다.

| 갈래 | 구조 | 대표 논문 (모두 공식 코드 있음) |
|---|---|---|
| **End-to-end** | 영상 LLM 하나가 매 프레임 "말할지"와 "무엇을"을 함께 낸다 | VideoLLM-online (CVPR'24): 스트리밍 EOS로 침묵/발화 · MMDuet2 (ICLR'26): 응답 또는 "NO REPLY" · LiveCC (CVPR'25): 실시간 해설 |
| **분리형** | 가벼운 판단기가 "언제"를 정하고, 무거운 VLM은 그때만 부른다 | WalkVLM (ICCV'25): 3D CNN 트리거(TAP) → VLM · Dispider (CVPR'25): 판단 Qwen2-1.5B + 응답 Qwen2-7B 비동기 · StreamMind (ICCV'25): LLM 얕은 층으로 만든 게이트가 이벤트 때만 본체 호출 · StreamBridge (NeurIPS'25): 분리된 경량 활성화 모델 |

**분리형 논문들은 평가도 나눠서 한다.** 판단기와 응답을 각각 잰 뒤 전체를 잰다.
- WalkVLM (원문): 트리거는 시간 중복 F1(TRF)로, 문장은 텍스트 지표로 따로 잰다.
- Dispider (원문): 응답 시점은 ETBench 시간 F1로, 응답 내용은 StreamingBench로 잰다.

**우리 시스템도 분리형**으로 간다 (가벼운 트리거 + 필요할 때만 VLM). 그래서 다음 세 실험이 모두 필요하다.
1. 트리거만 비교해서, 어떤 "언제" 판단기가 좋은지 본다.
2. 트리거 시각을 고정하고 VLM 호출 방식만 비교해서, 어떻게 불러야 빠르고 정확한지 본다.
3. 전체 시스템을 end-to-end 단일 모델과 비교해서, 분리형이 실제로 이득인지 본다.

```
실험 ① 트리거            실험 ② VLM 호출                 실험 ③ 전체 시스템
영상 ─▶ [판단기] ─▶ 시각   시각(고정) ─▶ [호출 방식] ─▶ 문장   영상 ─▶ [시스템 전체] ─▶ (시각, 문장)
지표: PDR · 오탐 · 리드     지표: 지연 · 메모리 · 문장 정확도     지표: 전부 + 끝단 지연
```

## 1. 실험 ① — 트리거 ("언제")

### 1-1. 판단기가 어디에 있나로 나눈다

트리거를 비교하는 축은 **판단기가 모델의 어느 위치에 있느냐**다. 위치가 비용과 정확도를 함께 정한다.

| 위치 | 판단기 | 논문 · 코드 | 무거운 VLM과 공유하는 것 |
|---|---|---|---|
| **T-A 검출기 뒤** | 검출·추적 + 박스 크기 규칙 | B0 (1차 규칙, 기준선). 거리·칼만 기반 기하 트리거는 폐기 (`07` 문서) | 없음 (VLM 없이 동작) |
| **T-B 별도 경량 영상 모델** | 3D CNN + MLP → 위험 3단계 확률 | **WalkVLM TAP** (ICCV'25) · [xiaoyuan1996/walkvlm](https://github.com/xiaoyuan1996/walkvlm) (코드 확인) | 없음 |
| **T-C 시각 인코더 + 작은 LLM** | SigLIP 장면 분할 + Qwen2-1.5B 이진 분류 | **Dispider** (CVPR'25) · [Mark12Ding/Dispider](https://github.com/Mark12Ding/Dispider) (코드 확인) | 시각 특징 |
| | 경량 활성화 모델 | StreamBridge (NeurIPS'25) · [apple/ml-streambridge](https://github.com/apple/ml-streambridge) — **가중치 미공개, 학습 필요** | 시각 특징 |
| **T-D LLM 얕은 층** | LLM 앞쪽 블록을 복사한 Cognition Gate | **StreamMind** (ICCV'25) · [xinding-sys/StreamMind](https://github.com/xinding-sys/StreamMind) (코드 확인) | 인코더 + LLM 앞부분 |
| **T-E LLM 출력 (end-to-end)** | 다음 토큰이 침묵(EOS)인가 | **VideoLLM-online** (CVPR'24) · [showlab/videollm-online](https://github.com/showlab/videollm-online) | 전부 |
| | 응답 / "NO REPLY" | **MMDuet2** (ICLR'26) · [yellow-binary-tree/mmduet2](https://github.com/yellow-binary-tree/mmduet2) | 전부 |
| | 프레임별 경고 토큰 확률 | **VIABench TPAD** (벤치마크 공식 방식, 코드 미공개 → 원문대로 구현) + LLaVA-OV-1.5-8B · InternVL3.5-8B · Qwen2.5-VL-7B | 전부 |

### 1-2. 규칙
- 모든 방법은 출력 문장을 버리고 **경고한 시각만** 채점한다. 문장 품질은 실험 ②에서 본다.
- 각 방법은 원 논문의 fps와 기본 문턱으로 돌린다. 확률을 내는 방법(TAP, Dispider, TPAD)은 **오탐 1회/분에 맞춘 결과**도 낸다. 이 문턱은 평가 영상 밖에서 정한다.
- 주 결과는 제로샷이다. 학습 코드가 있는 WalkVLM TAP · StreamBridge는 VIABench의 **다른 영상**으로 학습한 결과를 따로 낸다.

### 1-3. 지표
- **PDR:** 정답 구간 안에 경고한 비율 (VIABench 원문 정의)
- **PDR (4 s 앞 허용):** VIABench 구간은 사람이 말한 시점이라 대상이 이미 1–2 m 앞인 경우가 많아서 함께 본다 (`labels/evidence/v2_audit/`)
- **오탐/분, 정밀도**
- **리드타임**
- **TRF** (WalkVLM 원문)
- **판단기 비용:** 프레임당 ms, GPU 메모리, 처리 가능 fps

## 2. 실험 ② — VLM 호출 ("무엇을", 효율)

트리거 시각을 고정하고, 그 시각에 VLM을 **어떻게 부르는지만** 바꾼다. 고정 시각은 두 가지다.
- **(a) 정답 시각:** 트리거 오차를 뺀 호출 방식 자체의 성능
- **(b) 실험 ① 최고 트리거의 시각:** 실제 조건

| ID | 호출 방식 | 논문 · 코드 | 핵심 |
|---|---|---|---|
| **K1 이벤트 때 새로 호출** | 최근 몇 프레임 + 대상 정보를 한 번에 넣고 답을 받는다 | WalkVLM (ICCV'25) — 트리거 후 과거 N프레임으로 VLM 호출 (원문) | 상태 없음, 매번 prefill |
| **K2 상시 KV 캐시** | 프레임을 계속 캐시에 쌓아 두고 이벤트 때 디코딩만 한다 | VideoLLM-online (CVPR'24) · StreamingVLM ([mit-han-lab/streaming-vlm](https://github.com/mit-han-lab/streaming-vlm), attention sink + 압축 KV) | prefill을 미리 해 둠 |
| **K3 비동기 응답** | 판단·인식은 멈추지 않고, 응답 LLM이 따로 돈다 | Dispider (CVPR'25, 응답 Qwen2-7B 비동기) · DriveVLM-Dual (CoRL'24) | 경고가 VLM을 기다리지 않음 |
| **K4 게이트 후 본체** | 얕은 층 게이트가 통과시킬 때만 LLM 나머지 층을 돌린다 | StreamMind (ICCV'25) | 인코더·앞 층 재사용 |
| **K5 시각 토큰 줄이기** | 프레임 토큰을 모으거나 버려서 넣는다 | LION-FS (CVPR'25) · [JiuTian-VL/LION-FS](https://github.com/JiuTian-VL/LION-FS) — Token Aggregation · Token Dropping (01 문서) | prefill 비용 감소 |

- **같은 VLM 본체**로 비교한다. 기본은 Qwen2.5-VL-7B (VIABench 평가 모델). K2·K4·K5처럼 자기 모델에 묶인 방법은 그 모델로 돌리고 따로 표기한다.
- 지시문은 VIABench 공개 reminder 지시문으로 통일한다.

**지표**

| 지표 | 정의 | 출처 |
|---|---|---|
| 첫 토큰 지연 · 전체 지연 | 트리거 시각 → 첫 토큰 / 문장 끝 (A5000) | 배포 조건 |
| GPU 메모리 · 동시 처리 | 최대 메모리, 실시간 배속 | — |
| **문장 정확도** | VIABench Mean Prompt Similarity (원문 보조 지표) + 대상 이름·방향이 영상과 맞는지 (LLM 판정 + 100개 사람 확인) | VIABench |
| 경고 지연 영향 | 경고가 VLM을 기다렸는지 (K3만 0이 되어야 함) | DriveVLM-Dual |

## 3. 실험 ③ — 전체 시스템 (end-to-end 비교)

| 시스템 | 구성 | 유형 |
|---|---|---|
| E2E-1 | VideoLLM-online | end-to-end |
| E2E-2 | MMDuet2 | end-to-end |
| E2E-3 | LiveCC | end-to-end |
| DEC-1 | WalkVLM (TAP + VLM) | 분리형 (원 논문 그대로) |
| DEC-2 | Dispider | 분리형 (원 논문 그대로) |
| DEC-3 | StreamMind | 분리형 (원 논문 그대로) |
| **Ours** | 실험 ①의 최고 트리거 + 실험 ②의 최고 호출 방식 | 분리형 |
| B0 | 1차 MVP | 기준선 |

**지표:** 실험 ①과 ②의 지표 전부 + **끝단 지연** (프레임 도착 → 첫 음성) + GPU 사용률 (분당 VLM 호출 수)

**확인할 가설:** "end-to-end 모델은 오탐과 GPU 비용이 크고, 분리형은 같은 PDR에서 오탐·지연이 작다."
- VIABench 원문: LiveCC는 재현율 75.8 %이지만 "조밀한 출력"이라 지적됐다.
- 오탐은 VIABench가 재지 않으므로 우리가 처음 재는 셈이다.

## 4. 넣지 않는 것

| 방법 | 이유 |
|---|---|
| RiskProp · DSTA | 대시캠 사고 예측 — 보행 1인칭 근거 없음 (원문) |
| ForeSightGuide · PathFinder | 공식 코드 없음, 학회 논문 아님 |
| HEADS-UP / MonoTransmotion | 보행자 궤적 전용, 스테레오 + VIO 전제 |
| TIMELI (ICRA'26) | 가중치 공개 여부 확인 후 실험 ①·③ 2순위로 |
| StreamBridge | 가중치 미공개 → 학습 데이터와 코드로 직접 학습해야 함 → 2순위 |
