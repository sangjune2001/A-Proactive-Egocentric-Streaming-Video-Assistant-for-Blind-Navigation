# P0 기준선 — 모델 · 프레임 선택의 근거와 비교 실험

## 0. 결론

1. **Qwen2.5-VL-7B는 근거 없이 고른 것이었다. 원문 표를 보면 1등도 아니다.** 우리 조건(정답 트리거 시각 직전 프레임을 주고 경고 문장만 생성)과 똑같은 VIABench Table 4에서 InternVL3.5-8B가 평균 43.9, Qwen2.5-VL-7B가 34.9다. 같은 계열 3B(36.8)보다도 낮다.
2. 대신 Qwen2.5-VL-7B는 **같은 32프레임에서 응답 4.6초, InternVL3.5-8B는 15.5초**다 (VIABench §8.3, L20 GPU). 정확도와 속도가 반대 방향이라 **논문만으로는 고를 수 없다 → 우리 데이터에서 모델 비교 실험(S-M)을 한다.**
3. **"최근 8프레임 · 4초"도 근거가 없었다.** 논문마다 1장 / 3장(1.5초) / 8장 / 32장으로 다르다. 그래서 논문에 나온 설정 네 가지를 그대로 비교한다(S-F).
4. VIABench는 프레임을 8 → 128장으로 늘려도 **"이득이 미미하다"**고 했다. 이유는 "보행 환경은 빨리 바뀌어서 오래된 프레임은 쓸모가 없다"는 것이다. 그래서 적은 프레임 쪽이 유력하지만, **움직임(접근 / 멀어짐)** 칸은 여러 장이 필요할 수 있어 실험으로 확인한다.

- 평균에는 우리와 관계없는 과제(표지판, 출입구, 카메라 이상 …)도 섞여 있다. 그래서 **OA · AA · PTL · 계단 열을 함께** 봐야 한다.

### 1-2. 속도 — (원문)

- VIABench §8.3: 32프레임에서 **Qwen2.5-VL-7B 약 4.6 s, InternVL3.5 약 15.5 s** (NVIDIA L20). 지연은 프레임 수에 따라 가파르게 늘어난다 (Figure 5).
- 경고 설명이 정답 구간 끝 + 2초 안에 들려야 점수가 나는 우리 지표(ESTP-F1)에서 **15초는 0점**이다. 그래서 정확도만으로 고르면 안 된다.

### 1-3. EgoBlind (NeurIPS'25 D&B) — 시각장애인 1인칭 질의응답, 질문 시각까지의 프레임만 사용 — (원문)

여기서도 Qwen2.5-VL-7B는 중하위다. 다만 구세대 모델 비교이고 InternVL3.5 · Qwen3-VL은 없다.

## 2. 프레임 수 · 시간 창 — 원문 근거

| 출처 | 설정 | 결과 / 근거 |
|---|---|---|
| **EgoBlind** (NeurIPS'25 D&B) | 질문 시각 **1장만** vs 여러 장 | 1장으로 바꾸면 **1.0–1.6 %p만 하락**. 단, 안전 경고 · 도구 사용 질문은 영상이 핵심 |
| **WalkVLM** (ICCV'25) | 과거 **3장, 2 FPS (1.5 s)** | 시각장애 보행 경고 생성의 원 설정. 프레임 수 실험은 없음 |
| **VIABench Table 5** (원문) | **8 / 16 / 32 / 64 / 128장**, 1 FPS | 늘려도 이득 미미. InternVL3.5-8B는 8장이 가장 좋고 128장에서 떨어짐 (44.8 → 42.1, PR). Qwen2.5-VL-7B만 소폭 상승 (34.8 → 37.5). PDF 텍스트 추출에서 행 이름이 한 줄 밀려 있어 순서대로 맞췄음 (원문 표로 재확인 필요) |
| **VIABench Table 4** | 트리거 직전 **32장** | 모델 비교의 공통 설정 |
| VIABench §8.2 | — | "보행 환경은 빨리 바뀌어서 몇 분 전 관찰은 금방 쓸모없어진다" |

**결론:** 논문 설정 네 가지를 그대로 비교한다. 우리가 만든 값(이전 문서의 "8장 · 2 fps · 4 s")은 근거가 없어 뺀다.

| ID | 프레임 | 샘플링 | 창 길이 | 출처 |
|---|---|---|---|---|
| **F1** | 1장 (트리거 시각) | — | 0 s | EgoBlind 단일 프레임 실험 |
| **F3** | 3장 | 2 FPS | 1.5 s | WalkVLM |
| **F8** | 8장 | 1 FPS | 8 s | VIABench Table 5 최소 설정 (InternVL · Kimi · MiniCPM 최고점) |
| **F32** | 32장 | 1 FPS | 32 s | VIABench Table 4 공통 설정 |

**가설:** 대상 · 방향 칸은 F1으로도 충분하다 (EgoBlind). **움직임 칸(접근 / 정지 / 멀어짐)은 F3 이상**이 필요하다. 지연은 F1 < F3 < F8 < F32.

## 3. 그 밖의 P0 설정과 근거

| 항목 | 선택 | 근거 · 이유 |
|---|---|---|
| 프레임 입력 방식 | **여러 장의 이미지**로 넣음 (모델의 "비디오" 입력 경로를 쓰지 않음) | 후보 모두 vLLM에서 다중 이미지를 지원한다. 비디오 경로는 모델마다 시간 압축 방식이 달라 같은 프레임을 넣어도 정보량이 달라진다. 타임스탬프는 텍스트로 붙임 |
| 프레임당 시각 토큰 | **약 256개로 맞춤** (Qwen: 448×448 화소 상한 / InternVL: 타일 1개 = 256 토큰) | InternVL3.5 공식 카드: 타일 1개 = 256 토큰, 비디오는 프레임당 타일 1개 권장. 모델 간 공정 비교. 실제 토큰 수는 로그로 기록 |
| 대상 지정 | 기본 = **트래커 bbox를 각 프레임에 빨간 박스로 그림** + 프롬프트에 "빨간 박스의 물체" | 시각 프롬프트 (ViP-LLaVA, CVPR'24). 다른 방식은 S1에서 비교 |
| 출력 | **JSON 스키마로 강제** (vLLM 구조화 출력) | 4칸 채점(09)이 파싱 실패 없이 돌아가게. 형식 오류율이 0이 되는지도 기록 |
| 생성 | greedy (temperature 0), `max_tokens` 64 | 재현성. 3회 반복 지연 측정과 같은 출력 |
| 서빙 | vLLM OpenAI 호환 서버, 비교군마다 같은 버전 | 같은 엔진에서 모델만 바꿔 지연 비교 |

## 4. 실험 순서 (09 문서 §6-2에 추가)

| 단계 | 질문 | 조건 | 고정 | 주 지표 | 채택 규칙 |
|---|---|---|---|---|---|
| **S0** | 끝까지 도나 | P0 (Qwen2.5-VL-7B · F8 · 박스 그림), D2 | — | 형식 오류율, 지연 | 오류 < 5 % |
| **S-M** | 어떤 모델 | InternVL3.5-8B · 4B · Qwen2.5-VL-7B · 3B · Qwen3-VL-8B | F8 (VIABench Table 5에서 다수 모델 최고점) · 박스 그림 | **ESTP-F1(칸)** + 설명 지연 + OVO-Bench RT | ESTP-F1(칸) 최고. McNemar로 유의차가 없으면 지연이 짧은 쪽 |
| **S-F** | 프레임 몇 장 | F1 · F3 · F8 · F32 | S-M 상위 2개 모델 | ESTP-F1(칸), **움직임 칸 정확도**, 설명 지연 | 같은 규칙 |
| S1 | bbox 넣는 방식 | 없음 / 박스 그림 / 좌표 텍스트 / 둘 다 / 크롭 + 저해상도 전체 | S-M · S-F 결과 | ESTP-F1(칸), 대상 혼동률 | 같은 규칙 |

- S0의 Qwen2.5-VL-7B는 **"채택"이 아니라 배관 점검용**이다. 가장 빠르고(4.6 s) vLLM 지원이 확실해서 파이프라인이 도는지 보는 데만 쓴다.
- S-M에서 이긴 모델이 P0의 본체가 된다. P1–P3(효율화)는 공식 코드가 Qwen2.5-VL 기준이므로, P0가 InternVL로 바뀌면 **"P0(InternVL) vs P0(Qwen) vs P1–P3(Qwen)"** 형태로 보고한다.
