## 0. 결론

1. 붙여 준 표(MVBench · Video-MME · LongVideoBench · OVOBench Realtime · Inf-Streams-Eval · LiveSports-3K CC)는 **StreamingVLM (ICLR'26)의 결과 표**다. 앞 4개는 **객관식 정확도**, 뒤 2개는 **GPT 판정 승률**이다. 둘 다 "**언제** 말했나"를 재지 않으므로 우리 과제의 주 지표로는 맞지 않는다.
2. 우리 과제(트리거 시각에 VLM을 불러 경고 설명)에 맞는 탑티어 지표는 **시점과 내용을 함께 재는 계열**이다. **ESTP-F1** (NeurIPS'25, 1인칭 Ego4D) · **PAUC** (ProactiveVideoQA) · **PDR** (VIABench) · **TRF** (WalkVLM, ICCV'25).
3. **주 지표 = ESTP-F1의 공식 그대로, 내용 점수만 LLM 판정 대신 09 문서의 4칸 채점으로 바꾼 것.** 시점 허용 폭(앞 1초 · 뒤 2초)과 시점 점수 식은 원문 그대로 쓴다.
4. 공개 벤치마크는 두 용도로만 쓴다.
   - **모델 고르기 · 능력 보존 확인:** OVO-Bench Real-Time (CVPR'25). 판정 모델이 필요 없는 객관식이라 A5000만으로 끝난다.
   - **우리 도메인 규모 늘리기:** VIABench 영상 (09의 D3)
5. **OpenAI API는 쓰지 않는다 (비용).** 주 지표 ESTP-F1(칸)은 4칸 채점이라 판정 모델이 필요 없다. 자유 문장 비교가 꼭 필요한 곳은 **오픈소스 판정 모델(Prometheus 2 / M-Prometheus)을 A5000에 띄워** 대신한다 (§5). 이 점수는 "비공식(오픈 판정)"으로 표기하고 논문 수치와 직접 비교하지 않는다.

## 2. 평가 지표 계열 — 탑티어 논문은 어떻게 재나

| 계열 | 대표 | 장점 | 한계 (우리 과제 기준) |
|---|---|---|---|
| **A. 객관식 정확도** | MVBench · Video-MME · LongVideoBench · OVO-Bench | 판정 모델 없음, 재현 쉬움 | 응답 **시점**을 안 봄. 질문이 주어진 상태라 "알아서 경고"와 다름 |
| **B. 판정 모델 점수 · 승률** | Inf-Streams-Eval · LiveSports-3K · EgoBlind(GPT 정/오) · VIABench MPS(GPT-5) | 자유 문장 평가 가능 | 판정 모델 편향: VIABLE (EMNLP'26) — 최고 판정 모델도 오류 진단 52.6 %, 자기 선호 94.2 % |
| **C. 시점 + 내용 결합** | **ESTP-F1** · **PAUC** · PDR · TRF | **늦은 정답 · 이른 오답 · 오탐**을 한 숫자에 반영 | 원문은 내용 점수에 LLM 판정 사용 → 우리는 4칸 채점으로 교체 |
| **D. 효율** | TTFT (StreamingTOM, CVPR'26) · 실시간 FPS (StreamingVLM, ESTP) · 최대 메모리 · 토큰 비율 (TimeChat-Online, FastVID) · 응답당 초 (VIABench: Qwen2.5-VL-7B 약 4.6 s) | 하드웨어에서 직접 측정 | GPU · 입력 길이에 따라 달라짐 → 같은 A5000, 같은 입력으로만 비교 |

**우리 선택:** **C를 주 지표, D를 비용 지표**로 쓰고, A는 모델 고르기와 능력 보존 확인용, B는 공개 벤치마크를 공식 방식으로 재현할 때만 쓴다.

### 2-1. ESTP-F1 (NeurIPS'25 "Eyes Wide Open", 부록 B.3) — (원문)

- 정답 g_k = (내용 o_k, 구간 [t_start, t_end], 최적 시각 t_opt). 예측 p = (내용, 시각 t).
- **매칭:** t ∈ [t_start − 1 s, t_end + 2 s] 이면 유효 (앞 허용 1 s, 뒤 허용 2 s).
- **t_opt:** 물체 인식 · 위치 · 속성처럼 "보이자마자" 답해야 하는 과제는 **t_start**, 사건 진행을 봐야 하는 과제는 구간 중점.
- **점수:** S(p, g) = [S_answer(1–5) + S_time(0–5)] / 10, S_time = 5 − 5·min(1, |t − t_opt| / scale), scale = max(1, (t_end − t_start) + 1 + 2).
- S(g) = 매칭된 예측들의 평균 (없으면 0).
- **ESTP-F1** = 2·Σ S(g) / (N + M − Σ I(S(g)=0) + 2·Σ S(g))  — N 예측 수, M 정답 수. 오탐(매칭 없는 예측)이 많을수록 분모가 커진다.
- 원문의 S_answer는 LLM 판정이다.

### 2-2. PAUC (ProactiveVideoQA, 학회 확인 필요) — (원문)

- 정답 구간 안에서 시간에 따라 "지금까지 낸 응답의 점수(0/1/2, LLM 판정)" 꺾은선을 그리고, 그 아래 면적을 최대 면적 (t_end − t_start)·2로 나눈다.
- 일찍 맞힐수록 면적이 커지고, 오답은 0점이라 침묵보다 나쁘지 않게 설계했다. ω = 0.5가 응답 시간 반영 설정이다.
- 사람 선호와의 일치도(Cohen κ)가 시간 미반영(ω = 1)보다 높다고 보고했다. 다만 [EGO]에서는 0.30 대 0.26으로 차이가 작다.
- 판정은 GPT-4.1 (OpenAI Batch API, README).

### 2-3. PDR (VIABench) — (원문)

- 정답 구간 [ts, te] 안에 맞는 과제의 안내를 하면 탐지. PDR = 탐지 수 / 정답 수. **오탐 감점 없음.**

## 3. 우리 과제 지표 (09 문서 보완)

### 3-1. 주 지표 — ESTP-F1(칸)

ESTP-F1 식을 **그대로** 쓰되 S_answer만 바꾼다.

```
S_answer = 1 + (맞은 칸 수)          # 대상 · 방향 · 움직임 · 행동 4칸 → 1–5, 원문 범위와 같음
t        = 설명 첫 소리 시각          # 트리거 시각이 아니라 사용자가 실제로 듣는 시각
t_opt    = t_start                   # 장애물 · 이동체 인식은 "보이자마자" 유형 (원문 규칙)
허용 폭  = 앞 1 s, 뒤 2 s             # 원문 그대로
```

- **정답 시각에 호출하는 실험(S1–S5):** 경고마다 예측이 하나이므로 ESTP-F1은 사실상 S(g)의 평균이 된다. 지연이 길수록 S_time이 깎이고, t_end + 2 s를 넘기면 0점이다.
- **실제 트리거 실험(S6–S7):** 트리거의 오탐이 N에 들어가 분모를 키운다. 그래서 "VLM으로 오탐을 거르면 ESTP-F1이 오르나"를 바로 볼 수 있다.
- **원문 LLM 판정 버전과의 비교는 하지 않는다** (API 키 없음). 발표 때 "내용 점수를 LLM 판정 대신 4칸 채점으로 바꿨다"는 점을 명시한다.

### 3-2. 함께 보고하는 지표

| 지표 | 근거 | 역할 |
|---|---|---|
| PDR, PDR(4 s 앞 허용) | VIABench | 문헌 비교용 시점 지표 |
| 완전 정답률(FCR), 칸별 정확도, 혼동률, 환각률 | 09 문서 | ESTP-F1이 왜 낮은지 원인 분해 |
| 적시 정답률(TCR) 곡선 | 09 문서 | 시간 여유별 그림 (발표용) |
| TTFT · 설명 지연 · 디코딩 tok/s | StreamingTOM · VIABench | 비용 |
| 실시간 배율 (처리 fps / 입력 fps) | StreamingVLM · ESTP | P3 · P5 상시 처리가 따라가는지 |
| 최대 GPU 메모리 · 시각 토큰 수 · 영상 1분당 GPU 초 | FastVID · TimeChat-Online | 비용 |

**표본 줄이기 규칙 (일주일 안에 끝내기 위해):** 공개 벤치마크는 **고정 시드로 층화 추출**한 부분집합에서 모든 비교군을 같이 돌리고, **같은 부분집합의 Qwen2.5-VL-7B 원본 점수를 기준**으로 상대 비교한다. 리더보드 수치와 직접 비교하지 않는다.
- OVO-Bench Real-Time: 과제별 50문항 (6과제 → 300). 모델 고르기에 이것 하나만 쓰므로, 첫날 7B 속도가 허락하면 **과제별 100문항(600)**으로 늘린다.
- 정확한 문항 수는 첫날 7B 처리 속도를 잰 뒤 확정한다.
- **한계:** OVO-Bench는 시각장애 보조 도메인이 아니다. 도메인 적합성은 우리 데이터(D1 · D2 · D3)의 ESTP-F1(칸)으로 판단하고, OVO-Bench는 일반 실시간 인식 능력 확인용으로만 해석한다.

## 5. OpenAI 대신 쓰는 오픈소스 평가 지표 · 판정 모델

### 5-1. 핵심: 이 벤치마크들의 판정은 "글 대 글" 비교라 영상이 필요 없다

EgoBlind · ESTP-F1 · PAUC · VIABench MPS의 GPT 판정은 모두 **모델 답 문장과 정답 문장을 비교**한다. 판정 모델이 영상을 볼 필요가 없으므로 **텍스트 판정 모델**로 바꿀 수 있다. 영상까지 보는 판정은 오픈 모델 신뢰도가 낮아서(아래 VIABLE) 쓰지 않는다.

### 5-2. 후보 (모두 가중치 공개, A5000 24 GB에 올라감)

| 종류 | 이름 | 학회 | 무엇을 하나 | 보고된 신뢰도 | 크기 |
|---|---|---|---|---|---|
| **텍스트 판정 (정답 참조)** | **Prometheus 2** | EMNLP'24 | 정답 문장 + 채점 기준표를 주면 1–5점 (절대 채점) 또는 둘 중 승자 (짝 비교) | 공개 판정 모델 중 사람 · GPT-4 판정과 상관이 가장 높고, GPT-4와의 격차를 절반으로 줄임 | 7B (8x7B도 있음) |
| | **M-Prometheus** | COLM'25 | Prometheus의 다국어판 | 다국어 평가에서 기존 공개 판정 모델보다 높음 | **3B · 7B · 14B** |
| | JudgeLM | ICLR'25 Spotlight | 답 채점 · 짝 비교 | GPT-4 판정과 일치율 90 % 이상 | 7B · 13B · 33B |
| 멀티모달 판정 | LLaVA-Critic | CVPR'25 | 이미지 · 영상과 답을 함께 보고 채점 | 여러 평가 벤치마크에서 GPT-4V/4o와 비슷하거나 높음 | 7B · 72B |
| **임베딩 유사도** | **BGE-M3** 코사인 유사도 | (임베딩 모델, 학회 확인 필요) | 문장 의미 유사도 0–1, 100개 이상 언어 | 한국어 미세조정판(`bge-m3-korean`) 한국어 STS Spearman 0.87 (모델 카드) | 0.6B |
| | BERTScore | ICLR'20 | 토큰 임베딩 매칭 F1 | — | 다국어 BERT |

**주의 — VIABLE (EMNLP'26):** 시각장애 보조 응답 판정에서 **오픈소스 판정 모델은 편향이 크고 적대적 입력에 약하다**고 보고했다 (GPT-5.4도 오류 진단 52.6 %). 그래서 판정 모델 점수는 **주 지표로 쓰지 않고**, 쓰기 전에 아래 5-4의 일치도 검사를 통과해야 한다.

### 5-3. 어디에 무엇을 쓰나

| 용도 | 방법 | 비고 |
|---|---|---|
| **주 지표 ESTP-F1(칸)** | 4칸 일치 (판정 모델 없음) | 변경 없음 |
| ESTP-F1 원문형 (자유 문장) | S_answer(1–5)를 **Prometheus 2-7B 절대 채점**으로 계산 | ESTP 원문과 같은 1–5 척도. VIABench(D3) 영어 정답 문장 기준 |
| VIABench MPS 대체 | **BGE-M3 코사인 유사도** (0–1) + Prometheus 2 점수 / 5 | MPS와 같은 0–1 범위. "MPS(오픈)"으로 표기 |
| 한국어 문장 품질 (D1) | **M-Prometheus-7B** (정답 `text_ref` 참조 채점) + BGE-M3(`bge-m3-korean`) 유사도 | 한국어는 M-Prometheus |
| EgoBlind (선택) | 공식 `eval.py`의 OpenAI 호출을 **로컬 vLLM 서버**로 바꿔 Prometheus 2가 정/오 판정 | vLLM 서버가 OpenAI와 같은 요청 형식이라 주소(`base_url`)와 모델 이름만 바꾸면 됨 (스크립트 호환 확인 필요). 점수는 비공식 |
| PAUC (P5 참고용, 선택) | 같은 방식. 0/1/2 채점을 Prometheus 2로 | 원문은 OpenAI Batch API → vLLM의 배치 실행 기능으로 대체 (확인 필요) |

### 5-4. 판정 모델을 믿어도 되는지 먼저 검사한다

판정 모델을 쓰기 전에 개발 세트(D2 + D3 일부)에서 확인한다.
- **4칸 채점과의 일치도:** 같은 예측에 대해 "4칸 모두 정답" 여부와 판정 점수(≥ 4점)의 **Cohen κ**, 맞은 칸 수와 판정 점수의 **Spearman 상관**.
- **위치 편향:** 짝 비교라면 A/B 순서를 바꿔 같은 승자가 나오는 비율.
- **통과 기준:** κ ≥ 0.6. 못 넘으면 그 판정 점수는 보고하지 않는다.
- 판정 모델은 비교군과 **다른 계열**을 쓴다 (Prometheus 2 = Mistral 기반, 비교군 = Qwen · VideoLLaMA 기반). 자기 선호 편향(VIABLE 보고)을 피하기 위해서다.

### 5-5. 비용

- 전부 A5000에서 돈다. Prometheus 2-7B (bf16 약 15 GB)는 VLM 실험과 **동시에 올리지 않고**, 비교군 출력을 다 모은 뒤 따로 한 번에 채점한다.
- 추가 비용은 GPU 시간뿐이고 API 비용은 0이다.
