# TTS 비교 실험 (docs/13 3단계)

작성 2026-10-07 · 담당 박상준 · 코드 `code/tts_bench/` · 결과 `results/tts_bench/`

> **이 문서의 위치:** 노트북 CPU(i5-1035G4)에서 **비교 실험 틀을 만들고 검증**한 단계다. 최종 수치는 A5000에서 같은 스크립트로 다시 낸다 (`setup_tts_server.sh` → `run_tts_bench.sh`).
> 문장 세트는 55개(경고 32 + 설명 23)뿐이다. 엔진 사이 큰 차이는 보이지만, 작은 차이(CER 0.01–0.02)는 의미를 두지 않는다.

---

## 1. 질문과 결정 기준

| 항목 | 내용 |
|---|---|
| 질문 | 어느 한국어 TTS가 **빠르고 · 정확하게 들리나** |
| 결정 기준 (docs/13) | 받아쓰기 오류율이 기준 이하인 엔진 중 **첫 소리가 가장 빠른 것** |
| 경고 문장 | 미리 합성해 두므로 합성 속도는 상관없고 **정확도만** 본다 |
| 설명 문장 | VLM 답이 나온 뒤 합성하므로 **첫 소리 시간이 설명 지연에 그대로 더해진다** (실행 시스템 로그로 확인: `code/runtime`) |

## 2. 문장 세트 (`sentences.py`)

실행 시스템과 **같은 코드**로 만든다 (TTS가 실제로 받을 문장만 평가).

| 묶음 | 개수 | 내용 |
|---|---|---|
| 경고 W | 32 | 즉시 경고 템플릿 전부 = 10클래스 × 왼쪽/정면/오른쪽 + "초록불로 바뀜", "빨간불로 바뀜" |
| 설명 D | 23 | `ko_template.sentence` 층화 추출 — S1 대상 7개(움직임 3종 고르게) · S2 장애물 세부 10종 · S3 신호 4종 · S4 계단 2종, 방향은 무작위(seed 0), 행동은 하이브리드 규칙표 |

| MMS-TTS-kor | VITS | CPU/GPU | CC-BY-NC 4.0 | Pratap et al., MMS (JMLR 2024) · 한국어는 uroman 로마자 입력 (모델 카드) | 노트북 · 서버 GPU |

- **복제형(zero-shot) 엔진**(CosyVoice2/3 · Chatterbox)은 참고 음성이 필요하다. 모두 **같은 참고 음성**을 쓴다: `prompt_ko.wav` (Supertonic F1로 합성한 6.5 s 한국어 문장, `make_prompt.py`). 그래서 목소리 차이가 비교에 섞이지 않는다. 사람 녹음이 아니라 저작권 · 동의 문제도 없다.
- 각 엔진은 **공식 README의 기본 사용법 · 기본 설정** 그대로 쓴다 (Supertonic steps 8 · speed 1.05, MeloTTS speed 1.0, CosyVoice `inference_zero_shot`).
- Windows 설치 메모 (노트북): MeloTTS의 한국어 발음 변환기 g2pkk가 Windows에서 `eunjeon`을 찾는데 배포판이 없다. 리눅스에서 g2pkk가 쓰는 `python-mecab-ko`(같은 MeCab-ko 사전)를 `eunjeon` 이름으로 연결하는 호환 모듈을 넣었다. 서버(리눅스)는 원래 경로를 쓴다.

## 4. 측정 (`synth.py` → `asr_eval.py`)

| 지표 | 정의 |
|---|---|
| 합성 시간 | 문장 하나 합성 벽시계 시간. 처음 2문장은 예열로 버림, 로드 시간은 따로 |
| 첫 소리 시간 | 스트리밍 엔진(CosyVoice `stream=True`)은 첫 조각까지, 나머지는 합성 시간과 같음 |
| RTF | 합성 시간 / 소리 길이 (1보다 작으면 실시간보다 빠름) |
| **CER** | Whisper large-v3로 받아 적은 글과 원문을 비교 (공백 · 문장부호 제외, 음절 단위 편집거리 / 원문 글자 수) |
| 문장 정확 | 받아쓰기가 원문과 완전히 같은 비율 |

- 받아쓰기: faster-whisper large-v3 (노트북 CPU int8 · 서버 GPU fp16), `language="ko"`, beam 5.
- 주의: 2–3음절 경고("오른쪽 킥보드")는 받아쓰기 모델이 짧은 소리를 놓치는 경우가 있다. 그래서 CER이 높게 나온 문장은 **직접 들어서** TTS 오류인지 받아쓰기 오류인지 확인한다 (6절).

## 5. 노트북 결과 (2026-10-07, i5-1035G4 8스레드, 다른 작업 없음)

**합성 속도**

| 엔진 | 로드 (s) ↓ | 합성 중앙 (s) ↓ | 합성 최대 (s) ↓ |
|---|---|---|---|
| Windows Heami | 0.4 | 0.024 | 0.064 |
| Supertonic-3 F1 | 3.7 | 1.99 | 5.50 |
| Supertonic-3 M1 | 2.5 | 1.55 | 4.62 |
| MeloTTS-Korean | 37.9 | 1.99 | 8.75 |
| MMS-TTS-kor | 51.5 | 10.06 | 13.33 |

**지표 읽는 법**

| 지표 | 뜻 | 계산 | 좋은 방향 |
|---|---|---|---|
| **경고 CER** | 즉시 경고 문장(32개, 예: "왼쪽 오토바이")이 얼마나 틀리게 들리나 | TTS 소리를 Whisper large-v3로 받아 적고 원문과 비교. 공백 · 문장부호를 빼고 **틀린 글자 수(삽입 · 삭제 · 바꿈) ÷ 원문 글자 수** → 문장마다 구해 32개 평균. 0.016 = 100글자 중 약 1.6글자 틀림 | **낮을수록 ↓** (0 = 완벽) |
| **설명 CER** | VLM 설명 문장(23개, 예: "정면에 자전거가 다가오고 있어요. 멈추세요.")의 오류율 | 위와 같은 방식, 23개 평균 | **낮을수록 ↓** |
| **문장 정확** | 한 글자도 안 틀리고 받아 적힌 문장 수 | 공백 · 문장부호를 뺀 받아쓰기 = 원문이면 정확. 55개(경고 32 + 설명 23) 중 개수 | **높을수록 ↑** |
| **합성 시간** | 문장 하나를 소리 파일로 만드는 데 걸린 시간 | 텍스트 입력 → wav 완성까지 벽시계 시간, 55문장의 중앙값. 모델 로드 · 예열은 제외. 노트북 CPU(i5-1035G4) 기준 | **낮을수록 ↓** (설명 지연에 그대로 더해짐) |

## 6. 직접 청취 판정과 해석 (10/8)

받아쓰기가 틀린 50문장을 박상준이 직접 듣고 판정 (`code/tts_bench/make_listen.py` → `results/tts_bench/listen.html`, 결과 `results/tts_bench/listen_verdicts.csv`).
판정: **TTS가 잘못 읽음**(소리만으로 원문을 못 알아들음) / **받아쓰기가 잘못 들음**(소리는 또렷, Whisper만 틀림) / **애매**.

| 엔진 | 받아쓰기 틀림 | TTS 잘못 | 받아쓰기 잘못 | 애매 | 들어서 맞는 문장 ↑ (/55) |
|---|---|---|---|---|---|
| **Windows Heami** | 5 | **0** | 5 | 0 | **55** |
| **Supertonic-3 M1** | 1 | 1 | 0 | 0 | **54** |
| MeloTTS-Korean | 13 | 0 | 11 | 2 | 53 (+ 애매 2) |
| Supertonic-3 F1 | 5 | 5 | 0 | 0 | 50 |
| MMS-TTS-kor | 26 | 24 | 2 | 0 | 31 |

| 판단 | 근거 |
|---|---|
| Heami "빨간불 → 밝은 불"은 받아쓰기 오류 | 소리는 "빨간불"로 또렷 → Heami 실제 오류 0, 합성 0.02 s |
| Supertonic은 짧은 경고 끝이 잘림 | M1 "정면 계단", F1 5개 모두 2–3어절 경고의 끝 잘림 (TTS 오류) |
| MeloTTS 오류는 대부분 받아쓰기 쪽 | "정면 → 정년" 9개 중 7개 받아쓰기 · 2개 애매, 설명 앞부분 누락 2개도 받아쓰기 쪽. 단 합성 1.99 s |
| MMS 탈락 | 24개가 실제 TTS 오류 |
| **노트북 시연 = Heami** | 가장 정확(들어서 55/55) + 가장 빠름. 단 Windows 전용 → 서버 · 기기 탑재에서는 못 씀 |
| 서버용은 A5000에서 결정 | M1(짧은 경고 잘림 보완: 앞뒤 무음 패딩 · 속도 조절 등) vs CosyVoice2/3 · Chatterbox, 같은 받아쓰기 + 청취 절차 |
| 한계 | 한 사람이 원문을 보며 들음 (기대 효과로 TTS 오류를 적게 셀 수 있음). 받아쓰기가 맞은 문장은 다시 안 들음. 55문장 |

## 7. 서버(A5000)에서 할 것

```bash
FAST=/home/ubuntu/fast bash code/tts_bench/setup_tts_server.sh     # 엔진별 conda 환경 + CosyVoice 모델
FAST=/home/ubuntu/fast bash code/tts_bench/run_tts_bench.sh        # 9개 설정 합성 + GPU 받아쓰기 → summary_server.md
```
- Supertonic은 서버에서도 **CPU**로 잰다 (온디바이스 8–11주차 대비 기준).
- CosyVoice는 비스트리밍 / 스트리밍 둘 다 → 스트리밍 첫 소리 시간이 설명 지연을 얼마나 줄이는지.
- VLM(7B, bf16 약 16 GB)과 같은 GPU에 올릴 때의 메모리 · 지연은 2단계(스트리밍 실험)에서 실행 시스템으로 같이 잰다.
