## 1. 무엇을 했나

**목표:** 시나리오 4개(S1 이동체 · S2 장애물 · S3 신호 · S4 단차)의 "언제 말할지"를 학습 없이 기하 규칙으로 정한다.

```
영상 (15 fps)
 → E0 YOLO11s-seg + ByteTrack              물체·마스크·접지점
 → MoGe-2 ViT-S 깊이 (로컬 2 Hz)            미터 거리 + 화각
 → 시각 오도메트리 (깊이 + PnP, 0.5 s 간격)  내 속도 · 진행 방향
 → 미터 좌표 (진행 방향 기준 X, Z)
 → S1·S2  칼만 [x, z, vx, vz] + 내 속도 입력 + 64표본 충돌확률 (2차 트리거)
          + 정지물 4.5 m 거리 규칙
   S3     신호등 crop → TinyTLC + HSV → 안정 상태 전이
   S4     stairs 검출 (지면 기하 단서는 실패해 끔)
 → 스케줄러 → 템플릿 문장 → (VLM 검증은 서버 단계로 미룸)
```

## 4. 방법 비교 시도 (v1) — 설계 오류로 결과 무효

같은 입력(E0 + MoGe-2 + PnP 오도메트리) 위에 우리가 조합한 8가지를 비교했다.
- B 계열: looming TTC · 칼만 결정론 · 칼만 + 충돌확률 · IMM · 3D 연관
- C 계열: RANSAC 지면 + 통로 자유공간 · 깊이 최소거리 · 광류 발산

**잘못된 점**
1. **논문 방법이 아니라 우리 조합**이었고, 모든 방법이 같은 깊이 모델을 써서 MoGe 스케일 문제로 함께 무너졌다.
2. **스케줄러가 한 번 말하면 다시 말하지 않았다.** 점수가 계속 높은 방법은 첫 경고 뒤 침묵해서, 문턱을 넘고도 미탐으로 셌다.
3. **정답보다 일찍 말한 경고를 오탐으로 셌다.**
4. **문턱을 평가 10편에서 골라** 결과가 부풀려졌다. 처음 보고한 "C1 9/17"은 이 때문에 나온 수치다.

**고친 뒤 결과:** 평가 클립 밖 9편에서 문턱을 고르고 오탐을 1/분 이하로 맞추자, 모든 방법이 정답 13개 중 0–1개만 맞혔다 (B0는 오탐 14번에 5개).

## 5. 왜 폐기하나

1. **거리 스케일이 영상마다 흔들린다.** 단안 metric 깊이에 미터 문턱을 거는 방식은 클립이 바뀌면 문턱이 맞지 않는다.
2. **검출 기반이라 인식이 못 본 대상은 원리상 못 잡는다.** 이번 10편의 장애물 정답 상당수가 검출이 안 되거나 학습 클래스 밖이었다.
3. **부품 대부분이 우리 조합이다.** 오도메트리, 크기 게이트, 거리 규칙, 스케줄러가 그렇다. 탑티어 근거와 공식 코드가 있는 방법으로 비교하는 것이 맞다 → 05 문서.
