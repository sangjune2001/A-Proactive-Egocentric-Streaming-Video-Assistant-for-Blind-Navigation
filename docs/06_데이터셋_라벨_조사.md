**가장 중요한 한 줄**

> 다섯 데이터셋 중 **"연속 스트림의 어느 순간에 시스템이 먼저 말해야 하는가"를 프레임 단위로 라벨링해서 공개한 것은 없다.**
> WAD/WRD는 *이미 잘라낸 3초 클립마다* 경고문이 붙어 있을 뿐이고,
> 트리거 분류기(EAD/OTP)를 학습시킨 위험도 라벨은 **실사 영상 20개에 수작업**으로 붙였다고만 되어 있다 (WalkVLM-LR 논문, 공개 파일에서 찾지 못함).
> EgoBlind/EgoLife의 시각 정보는 **사용자가 질문한 시각**이지, 시스템이 먼저 말할 시각이 아니다.

## 1. 태스크를 시간축으로 보면

"QA 데이터셋"이라는 말로 뭉개면 안 되는 차이가 여기서 나온다. 같은 QA라도 **질문이 들어오는 시점, 볼 수 있는 과거의 길이, 누가 시작하는지**가 전부 다르다.

### 1-1. WAD / WRD — 클립 단위 경고문 (시스템 주도)

```
원본 보행 영상 (수 분) ─────────────────────────────────────────────▶
                 [────────── 3초 클립 ──────────]
                  0   1   2   3   4   5   6   7   8     ← 키프레임 9장 (+ 프레임별 detection json)
                                                  ▲
                                   reminder 1문장 (클립 전체에 붙은 라벨)
                                   WalkStream 학습·평가 코드는 8.jpg 한 장을 VLM에 넣음
```

* **언제**: 라벨이 클립에 붙어 있다. 클립 안의 어느 순간인지는 없다.
  "원본 영상에서 왜 이 3초를 골랐는가"가 사실상의 트리거 정보인데, 그 선택 기준은 공개돼 있지 않다.
* **무엇을 보고**: 클립 프레임 (WalkVLM 논문은 과거 N=3프레임과 2 FPS 샘플링, WalkStream 코드는 마지막 키프레임 1장).
* **출력**: `"About five steps in the twelve o'clock direction, there is a pedestrian approaching."` — 시계 방향 + 걸음 수.

### 1-2. GuideDog — 시간 없는 단일 이미지 안내

```
보행 영상에서 10초 간격 이상으로 뽑은 한 장 ──▶ [S1 주변 묘사] [S2 장애물: 종류·시계방향·걸음수] [S3 요약·진행방향]
```

* **언제**: 없다. 사용자가 "지금 앞 상황 알려줘"라고 요청했다고 가정한 정적 태스크.
* **무엇을 보고**: 그 한 장만.
* 스트리밍 트리거 학습에는 못 쓰지만, **VLM 출력 문장 형식(S1~S3)과 공간 인지(깊이 비교) 평가**에 쓸 수 있다.

### 1-3. EgoBlind — 질문 시각까지의 과거만 보고 답 (사용자 주도)

```
0s ─────────────────────────── t = 0.99s ──────────────────────────────── 37.9s
[ 모델이 볼 수 있는 구간 ]      ▲ 시각장애인이 질문: "Is it safe to enter the elevator now?"
                               │ t 이후 영상은 사용 금지 (논문: timestamp-restricted)
                               └ 정답: "Yes, the elevator door just opened." (그 순간 상황 의존)
```

* **언제**: `start-time/s` = 사용자가 질문한 시각. 한 영상에 질문이 평균 약 3.9개 (test 실측), 시각은 흩어져 있다.
* **무엇을 보고**: `[0, t]` 구간. 논문 분석으로는 **t 시점 한 프레임만 줘도 정확도가 1~1.6 %p만 떨어진다** → 대부분 "지금 이 순간"을 묻는 질문이다.
* **정답**: 서로 다른 annotator가 쓴 1~4개. "I don't know"도 정답으로 들어 있다 (answer0 기준 11 %).

### 1-4. EgoLife — 수 시간 전 기억을 꺼내 답 (사용자 주도, 초장기 맥락)

```
DAY2 17:39:02 (target = 근거)                                   DAY2 22:11:28 (query)
─────────▲──────────────────────── 4.5 시간 ───────────────────────────▲──────▶
         "캘리브레이션 보드를 벽 모서리에 둠"                         "보드 마지막으로 쓴 게 언제?"
                                                                      A 12h  B 1day  ▶C 4.5h  D 8h
```

* **언제**: `query_time`. 질문 시점 장면 묘사가 `trigger` 필드에 있다 ("지금 보드가 바닥에 보인다" → 질문 유발).
* **무엇을 보고**: `target_time`의 장면. 질문 시점에서 **중앙값 5.9 시간 전** (A1_JAKE 500문항 실측), 논문 전체로는 66 %가 2시간 이상 전.
* 보행 안전과는 거리가 멀다. 우리에게 의미 있는 건 **메모리 설계(EgoRAG: 시간 단위 요약 → 검색)** 쪽이다.

## 2. WAD (Walking Awareness Dataset)

### 2-1. 출처 · 수집 (논문)

* 12,000 video–annotation pairs, 약 13시간, 유럽·아시아 10개 지역
* 20 %는 annotator가 직접 촬영, 80 %는 YouTube. 1080p~4K, 60 fps
* annotator 9명. reminder·QA는 사람이 쓰고 **GPT로 문장을 다듬은 뒤 사람이 검수**

### 2-2. 라벨 체계 (논문)

| 계층 | 필드 | 값 |
|---|---|---|
| 정적 속성 | weather | sunny / night / overcast / cloudy / indoor |
| | location type | busy street / road / restaurant / pedestrian path / corridor / bicycle lane / shopping mall / other |
| | traffic flow | low / mid / high (보행자 수 기준) |
| | **danger level** | **low / mid / high** ← TAP 트리거 3클래스와 대응 |
| | scene description | 도로 상황·보행 흐름 서술 |
| reminder (6종) | obstacle | 정지 장애물 |
| | intersection | 갈림길·교차로 |
| | road clear/narrow | 통행 가능 여부·폭 |
| | oncoming vehicle/person | 움직이는 장애물 |
| | road departure | 보도에서 벗어남 |
| | identifier | 표지·신호등·랜드마크 |
| QA (3종) | 거시 장면 인지 / 가시 범위 경로 계획 / 세부 지식 (간판·상호) | |

annotator는 이벤트 시점을 찍고, **시계 방향 + 걸음 수**로 위치를 기록했다 (카메라 원근 편향을 줄이기 위해).

### 2-3. 공개 파일 구조 (실측)

`wad_dataset.tar` = **129,317,722,074 bytes** (이름은 tar지만 gzip). Range 요청 지원.
앞 406 MB만 스트리밍 해제했다.

```
license
src_data/
  <clip>.mp4                 # 3.0초. 1920×1080@60 또는 544×960@30 (세로)
  <clip>.frame/
    0.jpg … 8.jpg            # 키프레임 9장 (논문은 10장이라고 씀)
    detect_0.jpg … 8.jpg     # detection 오버레이 이미지
    0.json … 8.json          # 프레임별 자동 검출 (JSONL)
  QA<clip>.frame/            # 이름이 QA로 시작하는 폴더 — QA 서브셋 클립으로 추정
```

`N.json` 한 줄 = 한 박스:
```json
{"label": "car_(automobile)", "probs": 0.5063, "boxs": [178.5, 508.6, 196.5, 519.0]}
```

* 라벨 어휘가 **LVIS 계열**이다 (`car_(automobile)`, `window_box_(for_plants)`, `short_pants` …).
  받은 WAD+WRD 샘플에서 **302종**이 나왔다. 상위: person, car, signboard, lightbulb, shoe, flowerpot, awning …
  → 사람 라벨이 아니라 **open-vocabulary detector 출력**이고, WalkVLM의 POLM(Priori-Object Location Module) 입력이다.
* **받은 앞부분에는 reminder·QA·장면 속성 텍스트 파일이 없었다.** 전체 tar에 있는지는 (미확인).
  대신 WRD test.json의 `frame_path`가 WAD 폴더명과 같은 체계라, **받은 WAD 폴더 41개 중 2개**는 WRD test 문장으로 라벨을 붙일 수 있었다.

### 2-4. 샘플 시각화 — `viz/wad/00.png` ~ `09.png`

9장 키프레임 × detection 박스 (p ≥ 0.4, 프레임당 상위 15개).
`07.png`(세로 영상, 킥보드가 늘어선 보도)처럼 **3초 안에서도 보행자가 지나가고 킥보드가 화면 오른쪽으로 빠지는 변화**가 보인다 —
클립 단위 라벨 하나로는 이 변화의 "언제"가 사라진다.

### 2-5. 태스크 정의 (논문)

| 태스크 | 입력 | 출력 | 지표 |
|---|---|---|---|
| Reminder | 과거 프레임 `[I_{t−N} … I_t]` + 검출 위치·종류 | 짧은 경고문 | ROUGE-1/2/L, TF-IDF, GPT Score |
| QA | 같은 입력 + 질문 | 답 | 같음 |
| **트리거 (TAP)** | 과거 N=3프레임 3D-conv 특징 + 이전 트리거 상태 | low / mid / high | **TRF** (예측 위험도 vs GT의 F1 — 말을 너무 자주/드물게 하는지) |

## 3. WRD (WalkStream Reminder Dataset)

### 3-1. 파일 (실측)

| 파일 | 크기 | 내용 |
|---|---|---|
| `WRD.zip` (train) | **374,884,830,692 bytes** | 클립 + 키프레임 |
| `WRD_test.zip` | 11,563,038,328 bytes | 1,006 mp4 + 키프레임 |
| `train_v4.json` | 30 MB, **JSONL 97,898행** | 라벨 |
| `test.json` = `test_src_v4.json` | 279 KB, JSONL 1,007행 | 라벨 (두 파일 동일 내용) |

한 행:
```json
{"video": "4950_1127download_formal_0911_short_acdd…_2100_2160.mp4",
 "frame_path": "4950_1127download_formal_0911_short_acdd…_2100_2160.frames",
 "reminder": "There is an iron fence about five steps away in the 12 o'clock direction.",
 "reminder_type": "obstacle reminder"}
```

| | train (샘플 10개) | test (샘플 10개) |
|---|---|---|
| 클립 | 3.0초, **854×480**, 30 fps | 3.0초, **1920×1080**, 60 fps (세로 영상 포함) |
| 키프레임 | `.frames/0..8.jpg` + `N.json` | `.frame/0..8.jpg` + `N.json` + `detect_N.jpg` |
| 이름 체계 | `<번호>_1127download_formal_…` | WAD와 같은 `2024091x-youtube_short_…` |
| `reminder_type` | **채워져 있음** | **1,007건 전부 빈 문자열** |

> 1차 데이터셋 정리(삭제됨) 1절의 "reminder 6종 분류는 train 쪽에 있을 것 — 확인 못 함"은 **확인됐다.** train에 있다.
>
> train 파일명 끝의 숫자 쌍(`_2100_2160`, `_0_360` …)이 원본 영상 안의 위치라면 스트리밍 트리거 라벨로 바꿀 수 있을까 싶어 확인했다 → **위치 복원에는 못 쓴다.**
> 97,898행 중 48,402행에 숫자 쌍이 있고, 그중 46,033행이 폭 360 (`_0_360` 등)이다.
> 같은 출처 영상·같은 숫자 쌍에 클립이 흔히 11~20개씩 붙어 있다 (한 출처 영상에 `_0_360`만 수십 건).
> 즉 숫자 쌍은 3초 클립 하나의 위치가 아니라 **더 큰 원본 조각의 식별자**로 보이고, 조각 안 어디서 잘랐는지는 파일명에 없다 (실측).

### 3-2. 라벨 분포 (실측, train 97,898)

![](viz/stats/wrd_train_reminder_type.png)

* obstacle 56.8 % · oncoming vehicle/person 29.1 % · (유형 없음) 8.8 % · intersection 5.3 % · road clear/narrow 5.1 % · identifier 0.4 % · road departure 0.1 %
* 한 클립에 유형 2개 이상: 5,294건 (가장 흔한 조합 = obstacle + oncoming, 3,812건)
* 문장 길이 중앙값 **14 단어** (평균 15.0). **시계 방향 표현 84.3 %** (test는 73.9 %)

![](viz/stats/wrd_train_reminder_len.png)

### 3-3. 샘플 시각화 — `viz/wrd_train/`, `viz/wrd_test/`

* `wrd_train/00.png` — 철제 펜스 앞. 라벨 *"iron fence about five steps away in the 12 o'clock direction"*.
  detector는 펜스를 `pole`, 기둥을 `clock_tower`로 잡는다 → **detection 어휘와 reminder 어휘가 일치하지 않는다.** VLM이 픽셀을 봐야 하는 이유.
* `wrd_test/03.png` — 가로수길, 버스·자전거가 다가옴. 라벨 *"there is an oncoming vehicle ahead, please pay attention to safety"*.
  8장에 걸쳐 자전거 박스가 커지는 게 보인다 — **이 "커짐"이 우리 기하 feature(TTC)가 잡는 신호와 같은 것**이다.

### 3-4. 이 데이터로 무엇을 학습하나 (WalkStream 코드 실측)

| 모듈 | 파일 | 입력 | 라벨 | 비고 |
|---|---|---|---|---|
| Reminder 생성 (GRPO) | `reminder_generation/…/grpo_query_gene.py` | `frame_path/8.jpg` 1장 | `reminder` 문장 | Qwen2-VL-2B, 보상 = 간결성·유창성·정확도·키워드 |
| 트리거 (OTP) | `otp/train.py` | `*_features.json`의 `visual_features` (Qwen2-VL 비전 인코더 출력, 1536-d, 프레임 시퀀스) | `label` 마지막 토큰 ∈ {A, B, C} | **A=low / B=mid / C=high 위험 (WalkVLM-LR 논문)**, 추론 시 C가 있으면 VLM 호출 |
| 평가 | `otp/test.py` | `8.jpg` | test.jsonl `reminder` | ROUGE-1/2/L, keyword density, (선택) GPT score |

**OTP 학습용 `*_features.json`과 A/B/C 라벨은 WRD 공개 파일에 없다.** 논문은 실사 보행 영상 20개를 일정 간격으로 샘플링해 프레임마다 위험도를 수작업 라벨링했다고 적었다.

## 4. GuideDog

> ⏳ **샘플 다운로드 대기.** HF 게이트(자동승인) — 사용자 계정으로 동의 후 `huggingface-cli login` 필요.
> 아래 스키마는 HF 데이터 카드 기준(실측), 통계는 논문 기준.

### 4-1. 수집 (논문)

* YouTube 보행 영상 269개, 46개국 183개 도시, 약 291시간 후보 → 도시당 5개·지역당 10개 상한으로 균형
* 10초 간격 이상으로 프레임 샘플링, DINO로 중복 제거, EgoBlur로 얼굴·번호판 가림
* **silver**: YOLO-World(BLV 관련 80클래스) + depth 추정 → MLLM이 S1~S3 형식으로 생성
* **gold**: 사람 3명이 검수 (이미지 부적합 26.5 % 탈락, 기준 미준수 8.1 % 탈락, 장애물 정보 수정)

### 4-2. 라벨 형식 — 세 가지 기준 (논문)

| 기준 | 내용 | 예 |
|---|---|---|
| **S1** 주변 묘사 | 위치·주요 환경 | *"You are on a busy pedestrian street with shops on both sides…"* |
| **S2** 장애물 | 종류 + **시계 방향** + **걸음 수** + 위험 | *"Directly ahead at 12 o'clock, approximately 4 steps away, there is a sign post…"* |
| **S3** 요약·방향 | 직관적 단위로 진행 지시 | *"proceed straight ahead with slight adjustments to avoid people at 12 and 2 o'clock."* |

### 4-3. HF 스키마 (실측, 데이터 카드)

| config | split | 행 | 필드 |
|---|---|---|---|
| `default` | gold / silver | 2,106 / 19,978 | `image`, `gold_label`, `silver_label`, `scene_location`, `scene_description`, `video_country`, `video_city` |
| `depth` | train | 383 | `image`, `choices`, `closer`/`farther` 각각 `_raw`, `_bbox`, `_ratio_bbox`, `_direction`, `_depth`, `_confidence` |
| `object` | train | 435 | `image`, `answer_raw`, `answer`, `answer_bbox`, … |

용량: default 4.69 GB (gold 253 MB), depth 368 MB.

### 4-4. 태스크 (논문)

| 태스크 | 입력 | 출력 | 결과 |
|---|---|---|---|
| Guidance 생성 | 이미지 1장 | S1–S3 문단 | GPT-4o ROUGE-L 0.399 / LoRA Qwen2.5-VL 0.400 |
| GuideDogQA-object | 이미지 + 4지선다 "어떤 물체가 있나" | 선택 | LLaVA-OV 87.4 % |
| GuideDogQA-depth | 이미지 + "어느 게 더 가깝나" | 선택 | 대부분 우연 수준(25 %), GPT-4o 67.1 % |

→ **깊이(거리) 판단이 가장 약하다.** 우리 설계에서 depth를 VLM에게 맡기지 않고 별도 신호로 주는 근거가 된다.

## 5. EgoBlind

### 5-1. 수집 (논문)

* 시각장애 크리에이터가 Bilibili·TikTok에 올린 1인칭 영상 1,392개 (가슴 GoPro 또는 손에 든 폰)
* 평균 40초, 82.3 %가 1분 미만. 관심 대상이 **화면 중앙에 없고 초점이 안 맞는 경우가 많다**
* 질문 5.3k — 영상 속 발화 추출(541) / GPT-4o 생성 후 시각장애인 검수 / 시각장애인 직접 작성
* 답변: 대학생 21명이 영상을 보고 작성, 질문당 1~4개

### 5-2. 파일 (실측)

| 파일 | 행 | 필드 |
|---|---|---|
| `test.csv` | 2,565 | `question_id, video_name, question, answer0..3, type, start-time/s` |
| `test_half_release.csv` | 1,283 | 위와 같음 (정답 공개) |
| `test_half_hold.csv` | 1,282 | `question_id, video_name, question, start-time/s` (**정답 비공개**) |
| 영상 | 656 (test) | Google Drive 분할 zip. `split_0.zip`(2.48 GB)에서 Range로 10개만 추출 |

받은 영상: 1920×1080 또는 **1080×1440(세로)**, 30 fps, 5.4초~117.7초.

### 5-3. 분포 (실측, test)

![](viz/stats/egoblind_test_type.png)

![](viz/stats/egoblind_test_start_time.png)

![](viz/stats/egoblind_test_q_per_video.png)

* 질문 시각 중앙값 **14.0초**. 30초 안에 대부분 몰려 있다
* 질문 7.8 단어, 첫 번째 답 5.4 단어. 정답 개수 분포: 3개 1,106 / 2개 732 / 1개 649 / 4개 78 (비어 있지 않은 칸 기준 평균 2.24)

### 5-4. 샘플 시각화 — `viz/egoblind/`

영상마다 **상단 시간축**(세로선 = 질문 시각, 색 = 유형) + 질문 6개를 시간축에서 고르게 골라 `t−2초`, `t` 프레임과 정답을 나란히 보여준다.

`00_00962.png` (엘리베이터) 에서 보이는 것:
* **0.99초 한 시점에 질문 3개**(안전·도구·길찾기)가 동시에 달려 있다. 같은 장면에서 여러 의도를 뽑아낸 것
* *"Is it safe to enter the elevator now?"* → *"Yes, the elevator door just opened."* — **"now"의 답이 그 프레임에 달려 있다**
* *"Which button should I press to go to the third floor?"* 정답 4개 중 3개가 "모르겠다/주변에 물어보라" — **확신 없으면 모른다고 답하는 것도 정답**

### 5-5. 태스크 정의

| | |
|---|---|
| 트리거 | **사용자 질문** (시스템이 먼저 말하지 않음) |
| 입력 | 영상 `[0, start-time]` + 질문 텍스트 |
| 출력 | 자유 서술 한두 문장 |
| 평가 | GPT-4o-mini가 정답 후보들과 비교해 정/오 판정 → 정확도 (사람-기계 Kappa 0.88) |
| 기준선 | 사람 87.4 % / GPT-4o 59.3 % / Gemini 2.5 Flash 56.0 % / InternVL2.5-26B 55.0 % |
| 가장 어려운 유형 | **Navigation** (거의 모든 모델에서 최저) |

**우리에게 의미**: "safety warnings" 619문항은 **사용자가 물었을 때의 정답 안전 판단**이다.
시스템이 먼저 말하는 트리거의 정답은 아니지만, **트리거 발화 후 VLM이 내놓을 문장의 품질 평가셋**으로 쓸 수 있다.

## 6. EgoLife

### 6-1. 수집 (논문)

* 6명이 7일 동안 한 집(EgoHouse)에 살며 Meta Aria 안경으로 하루 약 8시간 촬영, 보존 266시간
* 3인칭 GoPro 15대, mmWave 레이더
* 자막: ASR → 화자 분리 → 사람 검수. 캡션: 2.65초 단위 짧은 서술 361k개 → 병합 25k개

### 6-2. 파일 (실측, HF `lmms-lab/EgoLife`)

| 파일 | 형식 |
|---|---|
| `A1_JAKE/DAY?/DAY?_A1_JAKE_HHMMSSff.mp4` | **30초 조각**, 1408×1408 어안, 20 fps, 화면에 시각 표시 |
| `DenseCaption_DAY?_HH.srt` | 시간별 파일. **중국어 1인칭 서술** ("我一点一点地扫描客厅") |
| `Transcript_DAY?_HH.srt` | 시간별 파일. `Jake: 呃是` + 영어 번역 |
| `EgoLifeQA_A1_JAKE.json` | 500문항 |

QA 한 건 (A1_JAKE ID 159):
```json
{"query_time": {"date": "DAY2", "time": "22112801"},
 "type": "EntityLog", "need_audio": false, "need_name": false, "last_time": false,
 "trigger": "In the room outside, the lights are bright, and there is also a calibration board on the ground",
 "question": "When was the calibration board on the ground last used?",
 "choice_a": "About twelve hours ago", …, "answer": "C",
 "target_time": {"date": "DAY2", "time": "17390210"},
 "keywords": "use calibration board",
 "reason": "I placed the calibration board in the corner of the wall"}
```
(모든 텍스트 필드에 `_chinese` 짝이 있다)

### 6-3. 분포 (실측, A1_JAKE 500)

![](viz/stats/egolife_type.png)

![](viz/stats/egolife_gap_hours.png)

* EventRecall 126 · EntityLog 125 · RelationMap 125 · TaskMaster 63 · HabitInsight 61
* `need_audio` 202 · `need_name` 318 · `last_time` 165
* 질문–근거 간격 중앙값 **5.9시간**, 47시간 부근(이틀 전)과 72시간 이상에도 뭉쳐 있다

| 유형 | 묻는 것 | 예 |
|---|---|---|
| EntityLog | 물건의 마지막 사용·위치·가격 | "보드를 마지막으로 쓴 게 언제?" |
| EventRecall | 과거 사건 회상 | "Katrina가 춤을 제안했는데, 전에 뭘 제안했지?" |
| HabitInsight | 습관 패턴 | "화이트보드 글씨 대부분을 누가 썼지?" |
| RelationMap | 사람 간 상호작용·신원 | "방금 Katrina를 도와 꽃을 올린 사람은?" |
| TaskMaster | 이전 행동에 근거한 할 일 | "누가 꽃을 키울 계획이지?" |

### 6-4. 샘플 시각화 — `viz/egolife/`

한 장에 **질문 시점 프레임 3장 + 근거 시점 프레임 3장 + 선택지·정답·reason + 질문 직전 20초 캡션·자막**.
`00_id159.png`: 22:11:28에 폰으로 욕실을 스캔하다가 바닥의 체커보드가 보임 → 4.5시간 전 17:39:02 장면에서 같은 보드를 들고 있음.

### 6-5. 태스크 정의

| | |
|---|---|
| 트리거 | 사용자 질문 (`trigger` = 질문을 유발한 현재 장면 서술) |
| 입력 | 질문 시각 이전의 **전체 과거** (최소 5분 전 근거, 논문) |
| 출력 | A–D 선택 |
| 기준선 | EgoButler(EgoGPT 7B + EgoRAG) 평균 36.0 %. 사람이 쓴 캡션으로 검색하면 45.5 % |

**우리에게 의미**: 보행 안전 데이터가 아니다. 가져올 것은 **EgoRAG의 시간 계층 메모리** —
"한 시간 요약 → 하루 요약"을 쌓아두고 필요할 때 검색하는 구조는, 보행 중 *"아까 지나친 횡단보도"* 같은 맥락을 VLM에 주는 방식으로 쓸 수 있다.

## 7. 우리 프로젝트와의 매핑

| 우리가 필요한 것 | 가장 가까운 공개 자원 | 부족한 점 | 메우는 방법 |
|---|---|---|---|
| **트리거 시점 라벨** (스트림에서 언제 말할지) | WAD danger level (논문), WRD 클립 선택 | 공개 파일에 프레임 단위 라벨 없음, WRD 파일명으로 원본 위치 복원도 불가 (3-1) | ① 자체 라벨링 (이벤트 + 유효 시간창, ESTP 방식) ② WalkVLM 저자에게 EAD 위험도 라벨 공개 여부 문의 |
| 경고 문장 형식 | **WRD 97,898문장** | 영어, 우리 trigger(신호등·킥보드) 희소 | 문장 템플릿 학습 + 한국어 변환 |
| 구조화된 장면 안내 | **GuideDog gold 2,106** | 정적 이미지 | VLM 출력 형식(S1~S3) 참고, depth QA로 공간 인지 평가 |
| 사용자 질문 응답 품질 | **EgoBlind safety/navigation 1,005** (test) | 사용자 주도 | 트리거 뒤 VLM 응답의 평가셋 |
| 장기 맥락 메모리 | EgoLife | 보행 도메인 아님 | 메모리 구조만 차용 |
| detection 사전 정보 | WAD/WRD `N.json` (LVIS 302종 이상) | 자동 검출 결과라 노이즈 | detector 교체 비교 기준선 |

## 8. 다운로드 재현 메모

| 대상 | 방법 | 주의 |
|---|---|---|
| WAD | `curl -r 0-N <tar URL> \| gzip -dc \| tar -x` 로 앞부분만 | 뒤쪽 truncate 에러 무시 |
| WRD | ZIP 꼬리 → 중앙 디렉터리 → 원하는 파일만 Range 추출 (`ziprange.py`) | **Python urllib Range 요청은 서버가 200(전체)으로 응답하는 경우가 있었다** → curl 사용. **크기 0인 zip 엔트리는 range 끝 < 시작이 되어 curl이 11 GB 전체를 받기 시작**하므로 반드시 건너뛸 것 |
| EgoBlind | Google Drive 분할 zip에 같은 Range 기법 | `video_source.bin` = 원 출처 URL CSV (재배포 시 출처 명시 조건) |
| EgoLife | HF 공개 파일 직접 GET | 참가자·일·시간 단위 경로 |
| GuideDog | HF 게이트 동의 → 토큰 → `load_dataset("kjunh/GuideDog", split="gold")` | CC BY-NC 4.0, 재배포 금지 |
